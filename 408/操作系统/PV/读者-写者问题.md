【问题描述】：  
- 系统中存在**两组并发进程**：**读者**和**写者**，它们**共享一个数据文件或记录**。**多个进程可同时读该文件**，但**任何写操作都必须与其他读/写操作互斥**。根据不同调度优先级策略，分为以下**两种变种**：
- 变种一（第一读者-写者问题 / **读者优先**）：  
    不让读者等待。若**已有读者在访问文件**，后续到达的读者**即使在有写者等待的情况下，也可立即进入读文件**。写者只有在**所有读者退出后**才能访问文件（可能导致**写者饥饿**）。
- 变种二（第二读者-写者问题 / **写者优先**）：  
    一旦写者就绪，尽可能快地执行写操作。若**已有写者在排队等待**，**后续到达的新读者将被阻塞**，不允许开始读操作，直到写者完成写操作退出（可能导致**读者饥饿**）。

- ① 首先，**编写程序核心代码**。
```cpp
void reader()
{
	while(1)
	{
		
		读文件
		int fd = open(".\file");
		read(fd);
		close(fd);
		
	}
}

void writer()
{
	while(1)
	{
		
		写文件
		int fd = open(".\file");
		write(fd);
		close(fd);
		
	}
}
```

- ② 然后，分析进程**同步关系**。（进程之间**有没有某个共同任务**？）
	- 同步关系：指多个进程为了**完成某个共同任务**而**协调执行顺序**，具有严格的“时序依赖（先 A 发生，后 B 才能发生）”。
	- 显然，读者和写者直接**没有直接的同步关系**。
		- 读者读文件，并不依赖写者刚刚写入了什么。
		- 写者写文件，也并不依赖读者刚刚读完了什么（它只是要求写的时候别人不能在里面）。
	- “**必须等别人出来，我才能进去**”：这叫“**互斥**”，不叫因任务协作引起的“同步”。（比如上厕所排队，你要等别人出来你才能上厕所。）

- ③ 最后，分析进程**互斥关系**。
	- 读者和写者之间有**互斥关系**（读-写互斥、写-写互斥）。
	- 只要有一个读/写进程在访问文件，其他写进程就不能访问文件。
	- 读者优先：当前是读进程在访问文件，后面到达的读进程都可以立即访问文件。
	- 写者优先：只要有一位写者在排队，后面到达的进程都不能立即访问文件。

- 先实现**读者和写者之间的互斥**，定义**互斥信号量rw**，初始值为1。
```cpp
semaphore rw = 1;

void reader()
{
	while(1)
	{
		P(rw);
		读文件
		int fd = open(".\file");
		read(fd);
		close(fd);
		V(rw);
	}
}

void writer()
{
	while(1)
	{
		P(rw);
		写文件
		int fd = open(".\file");
		write(fd);
		close(fd);
		V(rw);
	}
}
```

- 为了实现**读者优先**，还需要引入一个**计数值count**，用于**统计当前在访问文件的读进程个数**。
	- **第一个**读者访问文件时，P(rw)，把“门”锁上，只允许后面来的**读者**立刻进入。
	- **最后一个**读者关闭文件时，V(rw)，把“门”打开，允许后面来的**任意进程**进入。
	- count变量为**临界资源**，被**多个读者**共享，访问时需要用互斥信号量mutex实现互斥访问。
```cpp
semaphore rw = 1;
semaphore mutex = 1;
int count = 0;

void reader()
{
	while(1)
	{
		P(mutex);
		if (count == 0)
		{
			P(rw);
		}
		count++;
		V(mutex);
		
		读文件
		int fd = open(".\file");
		read(fd);
		close(fd);
		
		P(mutex);
		count--;
		if (count == 0)
		{
			V(rw);
		}
		V(mutex);
	}
}

void writer()
{
	while(1)
	{
		P(rw);
		写文件
		int fd = open(".\file");
		write(fd);
		close(fd);
		V(rw);
	}
}
```

- **写者优先**在此基础上，引入了**互斥信号量w**，初值为1，用于**阻断后面来的任何进程访问文件**。
	- w如同“门卫”:当有写者等待时,新读者无法进入: 但已在读的读者可正常完成操作,既保障了写者的优先权,又维持了读者之间的并发读取。
	- 读者在更新 count 后立即执行 V(w)，因为只要存在活跃读者(count > 0)，写者已被rw阻塞，提前释放w可避免不必要地阻碍其他写者。
	- 该算法本质上是在**防止写者饥饿的前提下**,对写者给予**有限优先**,**而非严格意义上的写者优先**。
```cpp
semaphore rw = 1;
semaphore mutex = 1;
semaphore w = 1;
int count = 0;

void reader()
{
	while(1)
	{
		P(w);
		P(mutex);
		if (count == 0)
		{
			P(rw);
		}
		count++;
		V(mutex);
		V(w);
		
		读文件
		int fd = open(".\file");
		read(fd);
		close(fd);
		
		P(mutex);
		count--;
		if (count == 0)
		{
			V(rw);
		}
		V(mutex);
	}
}

void writer()
{
	while(1)
	{
		P(w);
		P(rw);
		
		写文件
		int fd = open(".\file");
		write(fd);
		close(fd);
		
		V(rw);
		V(w);
	}
}
```
