- **信号量**是一种**功能强大的进程同步机制**，既能解决**互斥问题**，也能处理进程间的**同步问题**。

- 它仅能**通过两个标准原语访问**：
	- wait()，也称**P操作**
	- signal()，也称**V操作**
- **原语**是指完成特定功能且在执行过程中**不可被中断**的操作序列，通常**由硬件实现**。

## 整型信号量
- **整型信号量**用一个**整型变量S**表示**某类资源的可用数量**，不含阻塞队列。
- 与普通整型变量不同，对它只能进行**三种操作**：**初始化、wait(S)操作和signal(S)操作**。
```c
wait(S){
	while (S<=0);
	S = S - 1;
}

signal(S){
	S = S + 1;
}
```
- 在整型信号量中，当S<=0时，进程将持续**循环测试**，处于**忙等待**状态，不满足**让权等待**原则，会浪费CPU时间。

## 记录型信号量（⭐⭐⭐）
- 为了**克服忙等待**的缺陷，Dijkstra提出了**记录型信号量**。
- 它通过**阻塞机制**实现了**让权等待**。（⭐）

- **记录型信号量**采用**结构化数据表示**，包含两个主要内容：
	- **整型字段value**：表示当前可用资源数。
	- **进程链表L**：等待(阻塞)队列，用于**链接所有因请求该资源而被阻塞的进程**。
```c
typedef struct{
	int value; // 整型信号量，表示当前可用资源数
	struct process *L; // 等待(阻塞)队列
} semaphore;

// 相当于申请资源
void wait(semaphore S){
	S.value--; //先减
	if (S.value<0) // 减后value小于0，说明资源不足。
	{
		block(S.L);// 进程自我阻塞，把进程插入到阻塞队列末尾。
	}
}

// 相当于释放资源
void signal(semaphore S)
{
	S.value++; //先加
	if (S.value<=0) // 加后value小于等于0，说明必然有进程在阻塞队列中等待。
	{
		wakeup(S.L); // 移出并唤醒队首进程，将资源分配给它。
	}
}
```

## 利用(记录型)信号量实现互斥
- 若**某一临界资源需要被多个进程互斥访问**，可为该资源**设置一个互斥信号量S**，其**初值设为1**，代表只有1个临界资源。
- 随后，将各进程中**访问该资源的相关代码**(**临界区**)**置于P(S)与V(S)操作之间**。

- 互斥信号量**S≤0**时，|S|＝**阻塞队列中等待该临界资源的阻塞进程数量**。
- **互斥信号量**的设置准则：
	1. **不同类别**的临界资源应设置**独立的互斥信号量**，避免相互干扰。
	2. P(S)与V(S)必须**严格成对出现**。
	3. 若系统中存在**多个同类资源**，应将信号量初值设为**资源总数**。
```c
semaphore S = 1; // 记录型信号量声明+初始化，初值设为1，简写版（考试直接用）

P1(){
	... // 其余代码
	P(S); // 进入区，申请临界资源，加锁
	进程P1的临界区
	V(S); // 退出区，释放临界资源，解锁
	... // 其余代码
}

P2(){
	... // 其余代码
	P(S); // 进入区，申请临界资源，加锁
	进程P2的临界区
	V(S); // 退出区，释放临界资源，解锁
	... // 其余代码
}

// 其余进程以此类推
```

## 利用信号量实现同步
- 进程间的同步源于**合作的需求**。
- 在进程**并发**执行过程中，各个**进程具有异步性**，其**推进次序不确定**，即代码执行顺序不固定。这可能会导致进程**得出不符合要求的结果**。

- **同步信号量初值**的设定：
	1. 前驱同步：**初值通常设为0**。见下例。
	2. 资源计数同步：**由用户确定**。生产者-消费者问题里，**缓冲区有N个空位，初值设为N**。

- 例如，为了**协调推进次序**，可引入一个**同步信号量S**，其**初值设为0**。（前驱同步关系）
- **同步信号量 S 初值为 0 的含义**  
	- 将 S 视为一种“**逻辑资源**”的计数器，初值 0 表示该资源初始不可用。
	- 进程 P1 在完成某段关键代码**后**，会“**生产**”一个该逻辑资源，执行 `S++`（V 操作）。  
	- 进程 P2 在执行后续代码**前**，必须“**消费**”该逻辑资源，即执行 `S--`（P 操作）；因此，若 S 为 0，则 P2 被阻塞，直到资源可用。 
	-  **初值为 0 的设计意图**：确保 P2 在 P1 尚未提供资源时无法继续，**强制 P2 等待**，从而在**异步环境**中**精准控制执行顺序**。
	- 该**机制**常用于线程/进程间的同步，保证 P1 的某段代码先于 P2 的某段代码执行，实现“先生产后消费”的次序约束。

```c
semaphore S = 0;
P1(){
	x; // 执行语句x
	V(S); // 执行语句x后，生产逻辑资源，通知P2
	... // 剩余代码
}

P2(){
	... // 剩余代码
	P(S); // 执行语句y前，需要消费逻辑资源，等待P1的通知
	y; // 执行语句y
}
```

- PV操作用法总结：
	- 在**互斥关系**中，P、V操作要**紧夹涉及临界资源的那段代码(临界区)**，中间**不得插入任何无关代码**。
	- 在**同步关系**中，前操作**后**执行V操作，后操作**前**执行P操作（前V后P）。（保证了前操作->后操作）

## 利用信号量实现前驱关系
- 信号量还可用于描述程序段之间的**前驱关系**。

- **每对前驱关系**都对应一个**同步问题**(同步关系)。
- 因此，可以为**每条前驱边**（每对前驱关系）设置一个**同步信号量**，**初值均设为0**。

- 可以视为：直接前驱**持有多个不同的逻辑资源**。
- 使用规则
	1. 前驱段执行完毕**后**，执行**V操作**，通知**所有直接后继**。
	2. 后继段开始执行**前**，执行**P操作**，等待**所有直接前驱**完成。

- 假设有前驱关系：P1->P2, P1->P3, P2->P3, P3->P4
```c
semaphore a12 = 0 , a13 = 0, a23 = 0, a34 = 0; 
// 这样命名的好处，a12代表：前驱是P1，后继是P2。
// 在P1(前驱进程)中，执行V(a12)；在P2(后继进程)中，执行P(a12)；看数字关系即可，带来一丝方便。
P1(){
	...;
	V(a12); V(a13); // 生产所有其持有的逻辑资源，通知所有直接后继
}
P2(){
	P(a12);
	...;
	V(a23);
}
P3(){
	P(a13); P(a23);
	...;
	V(a34);
}
P4(){
	P(a34);
	...;
}
```

## 分析进程同步和互斥问题的方法步骤
1. 关系分析
	- 识别参与并发的进程，厘清其间的关系：互斥关系、同步关系、前驱关系。
	- 每类关系均可映射到前述经典信号量模型。
2. 思路梳理
	- 根据各进程的操作流程，确定关键同步点，规划P、V操作的位置。
	- 可参考和类比典型场景。
3. 信号量设置
	- 基于上述分析，定义所需的信号量，明确其语义和初值，将P、V操作嵌入各进程的适当位置，避免死锁与饥饿。
