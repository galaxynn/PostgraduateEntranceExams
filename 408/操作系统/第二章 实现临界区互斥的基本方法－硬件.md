- 现代计算机**提供了特殊的硬件指令**，能够以原子方式对一个字进行检测和修改，或是交换两个字的内容。可利用它们实现**临界区的互斥访问**。

- 管理临界区时，可**将共享标志视为一把锁**，每个想要进入临界区的进程必须先**测试该锁**。
- 上锁：**设置标志位**为true。
- 由纯软件实现的算法2和算法3的缺点可知，**测试和上锁必须构成一个原子操作**。

## 中断屏蔽方法
- **关中断**是实现互斥**最简单**的方式之一。
- **CPU仅在响应中断时才可能发生进程或线程调度和切换**。（⭐⭐）
	- 原因：**进程调度程序运行在内核态**。而**只有(广义)中断**才能使CPU**从用户态切换到内核态**，从而**执行进程调度程序**。
- 做法：
	- 在执行临界区代码之前**关闭中断**，临界区代码执行完毕后再重新**开启中断**。

- 缺点：
	1. **限制了CPU的并发执行能力**，降低了系统效率。
	2. 若将关中断权限开放给用户进程，则存在**风险**。若某进程**关中断后未及时开中断**，可能会**导致系统死锁或崩溃**。
	3. 不适用于**多处理器系统**。因为只在某个CPU上关中断**无法阻止**其他CPU上的进程**并发访问**同一临界区。

## 硬件指令方法－TestAndSet指令
- 借助一条名为**TestAndSet的硬件指令**实现互斥，该指令是**原子操作**。
- **TestAndSet的硬件指令**的功能：**读取指定标志位(锁)的值**，并**立即将其置为true**（**一定**置为true，无条件判断），然后**返回读取到的旧值**。（一气呵成，原子操作）
	- 若lock原本为false，用TS指令获取锁后lock置为true，**刚好上锁**，一举两得，**既得知了锁状态，又将锁上锁**。（巧妙）
	- 若lock原本为true，用TS指令获取锁后lock置为true，**不影响**。

- 做法：
	- 为**每个临界资源**设置一个**共享布尔变量lock**(锁)，初值为false。
		- lock = true，表示该资源已被占用。
	- 进程在进入临界区之前，通过执行TestAndSet(&lock)尝试获取锁。
		- 若返回值为false，说明旧值为false，说明此前无其他进程在临界区，**获取锁的过程中已上锁**，此时**该进程已获得该锁，可以进入临界区**。
		- 若返回值为true，说明旧值为true，有其他进程在临界区，需**循环等待**。
	- 退出临界区时，在退出区，要将lock置为false。

- 优点：**适用于多处理器系统**，TS指令为原子操作。
- 缺点：等待进程会**循环执行TS指令**，形成**忙等待**，**不满足让权等待**原则。

## 硬件指令方法－Swap指令
- **Swap指令**，也可称为**XCHG指令**。
- Swap指令的功能：原子地**交换两个变量的值**。

- 其工作原理与TS指令本质相同：通过一次原子操作，**既获取了锁的当前状态，又将锁置为占用**。
	- lock = false, key = true 时，执行Swap指令后，值互换，key中保存lock的旧值 false，key初值为true，顺便将lock置为true，进程可以进入临界区。
	- lock = true, key = true 时，执行Swap指令后，值互换，不影响。
- 做法：
	- 与用TS指令实现类似，为**每个临界资源**设置一个**共享布尔变量lock**（锁），**初值为false**。
	- 在每个进程中定义一个**局部布尔变量key**，**每次尝试进入临界区前**将其**置为true**。相当于每次都将锁置为true。
	- 进程执行Swap(&lock, &key)后，key中保存了lock的旧值。
		- 若 key 为 false，说明此前无进程持有锁，当前进程成功获得临界区访问权。
		- 若 key 为 true，说明锁已被占用，进程需继续**循环等待**。
	- 退出临界区时，在退出区，要将lock置为false。
- 优点：
	1. 实现简单，正确性易于验证。
	2. 支持任意数量的进程，适用于多处理器系统。
	3. 系统中可存在多个临界区，只需为每个临界区分配独立的lock变量。
- 缺点：
	1. 等待进程**循环执行**Swap指令，形成**忙等待**，**违反了让权等待**原则，造成CPU资源浪费。
	2. **锁的获取顺序不确定**，可能导致某些进程长期无法获得访问机会，**产生饥饿现象**。
