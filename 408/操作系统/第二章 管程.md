- 在信号量机制中，每个访问临界区的进程都需**自行编写P/V操作**。
- **分散**的同步代码**增加了编程复杂度**，操作不当还**容易引发死锁**。

- 为了**简化进程同步控制**，操作系统引入了更高层的抽象机制：**管程**。

- 管程**将共享资源及其操作封装于一体**，**自动保证互斥访问**，程序员无需显式编写互斥代码；同时通过**条件变量**实现灵活的进程同步，降低死锁风险。

## 管程的定义
- 系统中的各类硬件资源和软件资源，均可通过**数据结构**进行**抽象描述**。
- 管程利用一个**共享数据结构**来表示系统中的**共享资源**，并将**对该数据结构的所有操作封装**为一组过程。
	 - 进程对共享资源的申请和释放都必须通过调用这些过程来完成。
	 - 这些过程可根据资源的当前状态决定是否允许访问，统一管理所有对共享资源的访问，实现进程互斥。

- 管程：**由共享数据结构**及其**操作过程**共同组成的**资源管理程序**。

- **管程**与**面向对象程序设计中的类**高度相似，管程有以下**特性**：
	1. 封装性：管程将对共享资源的操作**封装**起来，内部的共享资源只能被进程**自身的过程**访问。**外部进程必须通过调用这些过程才能访问资源**。
	2. 互斥性：**任意一时刻仅允许一个进程执行管程内的过程**（⭐），从而实现互斥访问。

- 管程和进程的主要区别：
	1. 进程拥有私有数据结构PCB，而管程管理的是公共数据结构。
	2. 引入进程是为了实现并发，引入管程是为了简化进程同步控制。
	3. 进程是**主动执行的实体**，而管程是**被动调用的模块**。
	4. 进程具有动态的生命周期，而管程是操作系统中的**静态资源管理模块**，供进程调用。

- 形式上，管程由以下**四部分**组成：
	1. **管程的名称**。
	2. 局部于管程内部的**共享数据结构**。
	3. 对该数据结构进程操作的**一组过程（函数）**。
	4. **对共享数据进行初始化**的语句。

## 条件变量
- 当一个进程**调用管程的过程**后，若因条件不满足**而需要等待**，它**必须释放对管程的占用**。否则，其他进程将**无法调用管程的过程**，导致系统停滞。

- 为了解决**这个**问题，管程中引入了**条件变量**，若进程不满足该条件，则进程将**主动阻塞**，并加入到该条件变量的等待队列中，以**释放对管程的占用**。
- 管程中可设置多个条件变量，**每个条件变量维护一个等待(阻塞)队列**，用于**记录所有因该条件而阻塞的进程**。

- 和记录型信号量类似，**条件变量**仅支持两种操作：wait() 和 signal()。
	- 当**条件变量x**所代表的**条件不满足**时，**调用管程的进程主动调用x.wait()**，将自身加入x的等待队列，变成阻塞态，并**自动释放管程**。
	- 当**条件变量x**所代表的**条件已满足**时，**调用管程使条件满足的进程调用x.signal()**，**唤醒**一个因等待该条件而阻塞在x上的进程，变成就绪态。

- **条件变量**和**记录型信号量**的比较：
	- 相似点：wait/signal操作与P/V操作**均可实现进程的阻塞与唤醒**，但其**具体功能不同**。
	- 不同点：信号量**具有整数值**，可以**反映可用资源数量**；而条件变量**不维护数值**，仅用于进程排队和通知，**只负责进程同步**，因为管程中有专门的共享变量。

- 管程的代码实现：
```c
monitor monitor_name {
    // 1. 共享变量声明
    shared variable declarations;

    // 2. 条件变量声明 (用于同步)
    condition x, y;

    // 3. 操作过程 (对外接口)
    procedure P1(...) { ... }
    procedure P2(...) { ... }

    // 4. 初始化代码
    initialization_code(...) { ... }
}
```


## 进程使用管程的例子
- 在生产者-消费者问题中，管程的定义（了解即可）：
```c
monitor ProducerConsumer { // 管程名称
    // 共享数据(结构)
    int count = 0; // 缓冲区产品数量
    condition full, empty; // 条件变量，每个条件变量维护一个等待队列

    // 操作过程1：生产
    void insert(Item item) {
        if (count == N) full.wait(); // 缓冲区满则等待
        count++;
        insert_item(item);
        if (count == 1) empty.signal(); // 通知消费者
    }

    // 操作过程2：消费
    Item remove() {
        if (count == 0) empty.wait(); // 缓冲区空则等待
        count--;
        if (count == N - 1) full.signal(); // 通知生产者
        return remove_item();
    }
}
```

- 进程调用管程：
```c
// 生产者进程
producer() {
    while(1) {
        item = produceItem(); // 生产产品
        ProducerConsumer.insert(item); // 调用管程的过程，插入已生产的产品
    }
}

// 消费者进程
consumer() {
    while(1) {
        item = ProducerConsumer.remove(); // 调用管程的过程，获取产品以进行消费
        consumeItem(item); // 消费产品
    }
}
```
