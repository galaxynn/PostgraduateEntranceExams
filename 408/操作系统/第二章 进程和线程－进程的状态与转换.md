
## 常见的5种进程状态
（图片：汤小丹-P41）
1. 就绪态。进程已分配到除CPU以外的所有必要资源，**只要再获得CPU，便可立即执行**。系统中的多个就绪进程的PCB，被排列成**就绪队列**。
2. 运行态。进程已获得CPU，其程序**正在执行**。在**单处理机系统**中（默认），同一时刻只能有**一个**进程处于运行态。
3. 阻塞态。正在执行的进程由于发生某事件（如I/O请求、申请缓冲区失败等）暂时无法继续运行时的状态。系统中的多个阻塞进程的PCB，被排列成**阻塞队列**。
4. 创建态。进程正处于创建过程中，尚未进入就绪态。创建态是一个短暂的中间过程。
5. 终止态。进程已完成执行（正常结束或强制终止），正在等待系统回收资源。

## 进程的状态转换
- 就绪态->运行态：处于就绪态的进程被**调度程序**选中，获得CPU的使用权，转入运行态。（进程调度）
- 运行态->就绪态：处于运行态的进程在一个时间片用完后（或被其他进程抢占CPU使用权），主动让出CPU，转回就绪态。
- 运行态->阻塞态：处于运行态的进程**主动**发起了某种等待操作（如某种I/O相关系统调用），因条件未满足而无法继续执行（如I/O请求、访问临界资源），进程便会**主动进入阻塞态**。（主动）
- 阻塞态->就绪态：处于阻塞态的进程等待的事件发生时（如I/O完成），相应的中断处理程序会将其状态由阻塞态修改为就绪态。（被动）

- 进程从运行态变成阻塞态是一种**主动**行为，而从阻塞态变成就绪态是一种**被动**行为。

## 进程控制
- **进程控制**是进程管理中最基本的功能，主要包括**创建、终止、阻塞、唤醒进程**。
	- **进程控制**一般是由**操作系统内核中**的**原语**来实现的，原语在执行期间不可被中断。（仍会被不可屏蔽中断中断，但不会破坏原语语义，因为不可屏蔽中断的处理程序被设计得极短。）

### 进程的创建
- 在操作系统中，允许一个进程创建另一个进程。
	- **父进程**：创建进程的进程。
	- **子进程**：被父进程创建的进程。子进程可以继续创建更多的孙进程。
	- 子进程在创建时会**复制**父进程的**代码段、数据段、堆栈内容**、打开的**文件描述符**、环境变量等，但**拥有独立的虚拟地址空间**。
	- 也就是说，**父进程与子进程是相互独立的进程**，拥有各自独立的PCB和虚拟地址空间。
	- 子亡父不亡，父亡子不一定亡。

- 引起进程创建的事件：
	1. **用户登录**。用户在终端输入登录命令后，**登陆成功**时系统将会建立一个进程。
	2. **作业调度**（高级调度）。把作业装入内存后，系统会为其创建进程。（作业：在**外存**中的程序。）
	3. **提供服务**。用户程序提出某种请求后，系统将**专门创建**一个进程来提供服务。
	4. **应用请求**。应用程序为了**加速任务完成**，请求创建多个子进程并发进行。

- 操作系统通过**创建原语Creat**，按下述步骤创建一个新进程：
	1. **分配唯一标识符，申请空白PCB**。
	2. **为新进程分配其运行所需的资源**。包括各种物理和逻辑资源，如内存、文件、I/O设备和CPU时间等。这些资源或从操作系统获得，或**从其父进程继承**。
	3. **初始化PCB**。初始化PCB中的各种信息，通常将新进程设置为**最低**优先级。
	4. **插入就绪队列**。


### 进程的终止
- 引起进程终止的事件：
	1. 正常结束：进程任务完成，准备退出运行。
	2. 异常结束：进程在运行过程中发生严重错误，导致无法继续执行。常见原因为存储区越界、非法指令、算数运算错误、I/O故障、运行超时等。
	3. 外界干预：进程由外部实体的请求而终止运行，如操作员强制终止、父进程通过系统调用终止子进程等。

- 操作系统通过**终止原语Creat**，按下述步骤终止指定的进程：
	1. 根据被终止进程的标识符，在各PCB表或PCB队列中**查找其PCB**，并读取当前状态。
	2. 若被终止进程处于**运行态**，**立刻剥夺其CPU**，并触发调度程序选择下一个就绪进程。
	3. **释放该进程占用的所有系统资源**。
	4. 若系统支持**级联终止**，则**递归终止其所有子孙进程**；否则，不终止其子孙进程。
	5. 将该进程的PCB从所在队列（或链表）中移除。

### 进程的阻塞和唤醒
- 引起进程阻塞和唤醒的事件：
	1. 向系统请求共享资源失败。例如，操作系统无足够的资源。
	2. 等待某种操作的完成。例如，等待I/O操作完成。
	3. 新数据尚未到达。例如，等待另一个进程提供的数据。
	4. 等待新任务的到达。例如，完成某种任务的进程等待新任务。

- **注意**：**进程是可以占有I/O设备的**（占着茅坑），占用的I/O设备，在其PCB中记录。
	- **占有I/O设备≠处于阻塞态**，仅当需要等待I/O操作完成时，才会转为阻塞状态。
	- 进程可以在**运行态**主动释放I/O设备，也可以由操作系统释放其资源。

- **进程**通过**主动调用** **阻塞原语Block**，将自己从**运行态转为阻塞态**。
	- **阻塞是进程的主动行为**，只有处于运行态的进程才能阻塞自身。
- **阻塞原语**的执行过程如下：
	1. **保存当前进程的CPU上下文**（如PC、PSW、通用寄存器）到其PCB中的处理机状态信息中。
	2. 将其PCB中的现行状态**由运行态改为阻塞态**，并将该进程**插入到相应的阻塞队列**中。
	3. **调用调度程序**进行调度，将处理机分配给另一个就绪进程，进行**进程切换**。

- 当被阻塞进程所期待的时间发生时（如I/O操作完成，新数据或任务到达），则由**有关进程**（比如提供数据的进程，**内核的中断处理程序**）调用**唤醒原语Wakeup**将该进程从阻塞态转为就绪态。
- **唤醒原语**的执行过程如下：
	1. 在等待该事件的阻塞队列中找到目标进程的PCB。
	2. 将其从阻塞队列中移出，将其PCB中的现行状态设为就绪态。
	3. 将该PCB插入就绪队列。

- Block和Wakeup是一对作用刚好相反的原语，在使用它们时，**必须成对使用**。
	- 某进程调用**阻塞原语Block**阻塞自身，则必须在**与之相合作的、或其他相关的进程中**安排一条相应的**唤醒原语Wakeup**。
	- 否则，阻塞进程将会因不能被唤醒而**永久地**处于阻塞态。
