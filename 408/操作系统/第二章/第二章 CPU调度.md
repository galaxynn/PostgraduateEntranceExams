
## 调度的概念
- 背景：在多道程序系统中，进程数量通常远多于CPU的个数，存在多个进程**争用CPU**的情况。

- **处理机(CPU)调度**：**按照一定的算法，从就绪队列中选择一个进程，并将CPU分配给它运行**，从而实现多个进程的并发执行。

## 作业 vs 进程
- 作业：
	- 作业是**静态实体**，是**用户提交的程序、数据和命令的集合**。（被存放在**磁盘**里。）
	- 作业是**任务的提交单位**，由用户提交。
	- **1个作业可对应多个进程**。作业提交后，系统会**为该作业创建1个或多个进程**。（⭐⭐）
	- 因此，作业在逻辑上也是**可并发执行**的（**通过进程来实现**作业的并发执行）。
- 进程：
	- 进程是**动态实体**，是**程序在数据集上的一次运行活动**。（在**内存**中运行。）
	- 进程是资源分配和调度的基本单位，由**系统自动创建**。
	- **1个进程只属于1个作业**。

## 调度的层次
- 串联思路：**作业的生命周期**。
- 一个作业从提交到完成，要经历以下**三级调度**：
	1. 高级调度（作业调度）
		- 作业调度负责从**外存**后备队列中按照一定规则**挑选一个或多个作业**，为其分配资源，并**创建相应的进程**。
		- **作业调度实现了内存与外存之间的调度**。
		- 每个作业在其生命周期仅被调入一次，调出一次。**调度频率最低**。
		- 有些操作系统可以不配备高级调度。（如分时系统、实时系统）
	2. 中级调度（内存调度）
		- 当系统**内存紧张**时，它会将**内存中**某些暂时无法运行的进程（如处于**阻塞态**的进程）**换到外存**，此时的进程状态称为**挂起态**。
		- 当这些进程具备运行条件且内存有空闲时，中级调度再将其**换入内存**，恢复为**就绪态**。
		- 中间调度也是**内存和外存之间**的调度。实际上就是存储器管理中的**对换功能**（Swap）。
		- 有些操作系统可以不配备中级调度。
	3. 低级调度（进程调度，CPU调度）
		- 低级调度按照特定算法从就绪队列中选择一个进程，将CPU分配给它。
		- 低级调度的**调度频率最高**。
		- **所有**操作系统都**必须配备**低级调度。

- 三级调度的联系：
	- 低级调度是**最基本且不可或缺**的，高级调度和中级调度**可选择性配置**。
	- **三者调度频率依次升高**。
	1. 高级调度为进程活动做准备。
	2. 中级调度起调节作用。
	3. 低级调度驱动实际执行。

## 进程调度
### 进程调度的任务
- **广义的进程调度**包含**进程调度＋进程切换**。
- （广义）进程调度的任务：
	1. **选取**待运行进程。依据**调度算法**，从就绪队列中选取一个进程，并将其状态改为运行态。（狭义进程调度。）
	2. 保存**当前进程**的CPU现场信息。调度发生时，必须**将当前进程的CPU状态完整保存到其PCB中**。（进程切换。）
	3. 恢复**待运行进程**的CPU现场，完成CPU分配。由**分派程序**将选中进程的**PCB中保存的CPU现场**加载到CPU寄存器中，移交CPU控制权，使其**从上次断点处**恢复执行。（进程切换。）
### 进程调度程序
- 调度程序：用于实现CPU调度与分派的**软件组件**。（图－王道P68）
	- 调度程序是**操作系统内核程序**。
- 调度程序由**三部分**组成（以下三者，**不一定是顺序执行**的）：
	1. **排队器**。每当有进程**转换为就绪态**时，排队器将其**插入到相应的就绪队列**中。
	2. **分派器**。分派器依据**进程调度程序**所**选定的进程**，将其从就绪队列中取出，然后**触发上下文切换**，将CPU控制权转交给该进程。
	3. **上下文切换器**。在对CPU进行切换时，会发生**两对上下文的切换**：
		1. 将**当前进程的上下文**保存到其PCB中，再**切换到分派程序的上下文**，让**分派程序运行**。（当前进程->分派程序）
		2. 移除**分派程序的上下文**，将**选定进程的CPU上下文信息**装入CPU的各个寄存器。（分派程序->选定进程）

		- **上下文切换**需要执行大量load和store**指令**保存寄存器内容，**开销较大**。
		- **靠硬件实现**的方法来减少上下文切换时间：
			- 一般采用两组（或多组）寄存器，其中的一组寄存器供处理机在内核态时使用，另一组寄存器供应用程序使用。
			- 这样，在上下文切换时，**只需改变指针**，使其指向当前所需的寄存器组即可。

### 进程调度的时机
- 通常在以下条件下**需要进行进程调度与切换**（**运行态的进程转变为其他状态时**）：
	1. **创建新进程后**。若**新创建的进程的优先级更高**且支持抢占，则会发生进程调度与切换，即使不立即抢占，内核**也会设置"需要调度"标志位**。
	2. **当前进程正常结束或异常终止后**。若没有就绪进程，通常运行一个**闲逛进程**。
	3. **当前进程被阻塞**。
	4. **当I/O设备准备就绪后**，原先处于阻塞态的进程转换为就绪态时。
	5. 在支持**抢占**的系统中，**更高优先级的进程进入就绪队列**。
	6. **当前进程的时间片用完**。
	7. **当前进程出错**。**出错**指的是**异常里的终止**，致命错误，**系统会终止当前进程**。（⭐⭐）
	8. **中断处理结束**（可能、不一定）。时钟中断处理结束后，会发生进程调度与切换。
	9. 进程**处于临界区**时，是**可以被调度**的。（⭐⭐）


- **进程切换通常紧随调度之后发生**，其核心任务是保存原进程的执行现场，并恢复新进程的线程。

- 在以下情况**不能进行**进程调度与切换：
	1. 处理**中断**的**过程中**。
	2. 执行**原子操作**的**过程中**。
	- 若在以上**不可调度期间发生了调度条件**，系统会**设置一个调度请求标志**，待处理完成后再根据该标志执行相应的调度和切换操作。
	- 进程**处于临界区**时，是**可以被调度**的。（⭐⭐）

### 闲逛进程
- 当进程调度和切换发生时，若**系统中没有就绪进程**，系统会调度**闲逛进程**运行，其PID为0。
- **闲逛进程的优先级最低**，仅在无其他就绪进程时运行，一旦有就绪进程，就**立刻让出**CPU。
- 闲逛进程**不会占用除CPU外的系统资源**，也**不会进入阻塞状态**。

- 主要任务：在空闲循环中，**不断检测中断请求**。（因为**中断检测**通常发生在当前指令执行完成后的中断周期中）。

### 进程调度的方式
- 通常有以下两种进程调度方式：
	1. **非抢占调度方式**（非剥夺方式）
		- 即使有某个更为重要或紧迫的进程进入就绪队列，系统**仍让当前进程继续执行**。
	2. **抢占调度方式**（剥夺方式）
		- 若出现**更高**优先级的就绪进程，**调度程序暂停当前进程**，将CPU分配给更紧迫的进程。
		- 有利于**提高系统吞吐率和响应效率**，但不能任意抢占，要有一定的原则。

### 两种线程的调度
- **用户级**线程调度：内核不知道用户级线程的存在，内核**仍以进程为单位进行调度**。由**线程库**进行线程调度。若为**同一进程**内的线程切换，则**开销很小**。
- **内核级**线程调度：内核可以感知到每个内核级线程，内核**以线程为单位进行调度**。每次线程切换都需要从用户态转为内核态，**系统开销大**。

## 调度的目标
- 主要目标：**让进程轮流使用处理器**。同时，
1. 提高CPU利用率。
	- $CPU利用率 = \frac{CPU有效工作时间}{CPU有效工作时间+CPU空闲等待时间}$
	- 计算作业完成时间时，需要注意CPU和I/O设备之间、不同I/O设备之间可以**并行执行**。（画**甘特图**。）
2. 提高系统吞吐量。
	- 系统吞吐量：单位时间内系统完成的作业数量。
	- $系统吞吐量 = \frac{N}{t}, 其中, N为时间t内完成的总作业量$
3. 缩短周转时间。
	- **周转时间**：从**作业提交到作业完成**所经历的**总时间**。
	- $周转时间 = 作业完成时间 - 作业提交时间$
	- $带权周转时间 = 作业周转时间 / 作业实际运行时间$
	- $平均周转时间 = (作业1的周转时间 + \dots + 作业n的周转时间) / n$
	- $平均带权周转时间 = (作业1的带权周转时间 + \dots + 作业n的带权周转时间) / n$ 
4. 缩短等待时间。
	- **等待时间**：进程**在就绪队列中**等待CPU的**总时间**。
	- 若进程**不含I/O操作**，则**等待时间 ＝ 周转时间 - 运行时间（该进程使用CPU的时间）**。
5. 缩短响应时间。
	- **响应时间**：从用户**提交请求**到**系统首次产生响应**所经历的时间。**交互式系统**中，用户更关注响应时间。

- **不存在**一种调度算法能**同时满足**所有用户需求和系统目标。

## 进程切换
- **进程切换**是在**操作系统内核**的支持下实现的，是内核的功能之一。

### 上下文切换
- **上下文切换**：将**CPU切换到另一个进程**，需保存当前进程的状态，并恢复另一个进程的状态，这个任务称为上下文切换。
- **进程上下文**保存在其PCB中，包括PC、PSW、通用寄存器的值等。

- 上下文切换的**流程**：
	1. **挂起当前进程**，将当前CPU**上下文保存到其PCB**中。
	2. 将该进程的**PCB移入相应的队列**，例如就绪队列、阻塞队列。
	3. 调度程序**选择另一个进程**执行，并更新其PCB中的相关信息，如修改其状态。（进程调度）
	4. **恢复新进程的CPU上下文**。
	5. **跳转**到新进程PCB中的**PC所指向的位置**，开始**执行该进程的指令**。

- 上下文切换的**消耗**：
	- 上下文切换是一项**开销很大**的操作，每次切换需要**执行大量load和store指令**以保存和恢复进程上下文。
	- 可用**硬件方式**减少上下文切换开销。见上。

### 上下文切换与模式切换的区别（⭐⭐）
- 串联思路：一个进程的生命周期，如遇到系统调用或中断时会发生什么，被阻塞时会发生什么，被调度时会发生什么...。
- **CPU现场 ≠ 进程上下文**（⭐）：
	- CPU现场
		- **仅指CPU的硬件状态**（PC、PSW、SP、通用寄存器等）
		- CPU现场保存在**内核栈**中。
		- **模式转换**时（如中断、系统调用），会**保存CPU现场**。
		- 恢复速度：**微秒级**。
	- 进程上下文 
		- **进程上下文 ＝ CPU现场(硬件) ＋ 软件资源**（页表/内存映射、打开的文件描述符、信号向量、环境变量等）
		- **软件部分**保存在PCB和内存管理结构(MMU)中。
		- 上下文切换仅发生在**进程调度**时。
		- 恢复速度：**毫秒级**。恢复完整进程上下文需要**切换虚拟地址空间**（刷新TLB），开销大。
- 模式切换：
	- CPU状态在**内核态和用户态之间**的切换，对象是CPU状态。
	- 模式切换发生在**同一进程内部**，如当前进程**因系统调用或中断进入内核态**，**保存现场**，**跳转**到相应的服务程序执行，执行结束后，**恢复现场**，**返回用户态继续执行该进程**，当前进程并未改变，不涉及进程切换。（注：执行服务程序期间，原程序的确**暂停执行**了，但进程仍为**运行态**（若为非阻塞型系统调用），相当于**代码段的切换**。）
- 上下文切换：
	- **从一个进程切换到另一个进程**，保存旧进程的上下文，恢复新进程的上下文。
	- **保存现场和恢复现场 ≠ 上下文切换**，**换进程**才是上下文切换！
	- 上下文切换只能**由操作系统内核**完成，**整个切换过程运行在内核态**。

- 进程调度和进程切换的联系：
	- 调度是**决策行为**，决定将CPU分配给哪个进程。
	- 切换是**执行行为**，实际完成CPU控制权的转移。
	- **进程切换通常紧随进程调度之后发生**，调度后即**触发**上下文切换。
