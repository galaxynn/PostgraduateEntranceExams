- 下面通过用户发起的一次 **write 调用**来说明**I/O系统各层的功能**。

- ① 当用户要**向某设备写入数据**时，通过操作系统提供的 **write 命令接口**发起请求，该请求是从**用户层软件**发出的。
- ② 操作系统向上层提供的是**统一的通用接口**，即大多数设备都支持的标准命令，用户发出的 write 请求首先由**设备独立性层解析**，然后传递给下一层。
- ③ 不同类型设备对 write 命令的处理方式不同(如磁盘与打印机的行为差异显著)，因此需由**设备驱动层**将通用的 write 命令转换为设备特定的指令。
- ④ **设备驱动程序**将指令发送给**设备控制器**，启动实际的写操作。操作完成后，控制器向 CPU 发出**中断信号**，由**中断处理程序**响应。
- ⑤ **中断处理程序**确认写操作完成，清除中断标志，唤醒等待该操作的进程，并**将结果逐层返回至用户程序**，完成整个写操作。


- 上面从**理论上**说明了I/O请求在各层次间的传递过程。
- 下面结合Linux 系统中一次 write 系统调用的**实际执行流程**，**具体分析各层如何协作以及CPU 状态如何切换**。

- ![[第五章 5.1 IO操作举例 write流程.png]]

- ① 
	- 该流程始于**用户空间对库函数的调用**。用户程序调用 printf()后，经标准库内部封装，最终触发 write()系统调用的封装函数。
- ② 
	- 该封装函数生成的**机器指令序列**中**包含一条陷阱指令**(如IA-32 架构下的 int $0x80）。
	- 在执行该指令之前，若干传送指令会将**系统调用号**及**I/O 参数**(如文件描述符、 **缓冲区地址、字节数**)写入**指定寄存器**(如eax)。
- ③
	- CPU 执行**陷阱指令**后，产生一个**受控的软中断**，硬件自动完成**从用户态到内核态的模式切换**，并将控制权移交给**操作系统内核**。
- ④
	- 之后，CPU 跳转至**系统调用的统一入口程序 system_call()**（位于**内核空间**）。
	- 该程序根据寄存器 eax 中的**系统调用号**，通过**跳转表**将请求分派给对应的**系统调用服务例程 sys_write()**。
- ⑤ 
	- **sys_write()** 位于**设备独立性软件层**。
	- sys_write() 首先执行**与设备无关的公共操作**，如参数合法性检查、内核缓冲区分配与管理等。
	- 随后，它根据参数 (如**文件描述符fd**)**定位目标设备**，并调用对应的**设备驱动程序**。
- ⑥
	- 此时，进入**设备驱动程序层**。
	- **设备驱动程序**作为直接与设备控制器(I/O接口)交互的模块，负责将**抽象的I/O请求**转换为设备可识别的**具体命令**。
	- 设备驱动程序**初始化 I/O 接口、设置传输参数**，并**启动设备**进行数据传输。
	- 随后，通常**将当前进程置为阻塞态**，并调用**调度程序**主动**让出 CPU**给其他处于就绪态的进程运行。
- ⑦
	- I/O设备传输完成后，其**设备控制器**(I/O接口)向 CPU 发出**中断请求**。
	- CPU **响应中断**，**暂停当前程序的执行**，执行**中断隐指令**，切换为**内核态**，转入预设的**中断处理程序**。
- ⑧
	- 此时，进入**中断处理程序层**。
	- 中断处理程序读取设备状态，确认写操作是否成功，**清除中断标志**，并**唤醒等待该设备I/O的进程**。
	- 中断处理完毕后，切换回**用户态**，恢复现场，返回**被打断的进程**。
- ⑨
	- 当被唤醒的进程**再次获得 CPU 调度执行时**，会沿**内核栈**从设备驱动程序返回到sys_write()，再返回到system_call()。
		- 每个进程都有**独立的内核栈**，故进程调度时无需保存。
		- **调度程序本身位于内核态**，因此**可以直接跳转到位于设备驱动程序的断点处执行**，无需额外的模式转换。
	- 最终，在 **system_call() 末尾**通过执行 **iret** 等特权指令，**CPU 切换回用户态**，并在用户空间中**陷阱指令的下一条指令处**恢复执行。

- 由以上过程可知，一次完整的I/O请求依次穿越了用户层软件、系统调用接口、设备独立性软件、设备驱动程序和中断处理程序。
- 其中，**陷阱指令是从用户态进入内核态的唯一合法入口**，**中断是设备通知操作完成、触发进程状态转换的核心机制**。二者共同实现了用户态与内核态之间的安全切换。
