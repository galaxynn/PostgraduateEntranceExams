- I/O系统由**I/O软件**和**I/O设备（硬件）** 等组成。
- I/O软件涉及的面很宽，**向下与硬件密切关联**， **向上又与文件系统、虚拟存储器系统和用户直接交互**，它们都需要I/O系统来实现I/O操作。

- 为使复杂的I/O软件能具有清晰的结构、更好的可移植性和易适应性，目前已**普遍采用具有层次结构的I/O 系统**。
- 该结构是将I/O系统中的**设备管理模块**分为若干个层次，**每层**都是利用其**下层提供的服务(接口)** 来完成I/O功能中的某些子功能的，并且会屏蔽这些功能实现的细节，**向上层提供服务(接口)**。
	- 只要**层间接口保持不变**，任一层的修改都**不会影响**其他层次。
	- 仅**最底层**涉及硬件的具体特性。

## 1. 用户层软件
- 用于**提供与用户交互的接口**，用户可直接调用该层所提供的与I/O操作有关的**库函数**对设备进行操作。

- 通常，大部分 **I/O 软件**位于**操作系统内核**，但仍有**一小部分**驻留在用户层，例如**与用户程序链接的库函数**。
- 处于**用户层**的 **I/O 软件**必须通过**系统调用**获取操作系统服务。

## 2. 设备独立性软件
- **设备独立性**(也称**设备无关性**)：指应用程序在**使用 I/O设备时**，无须依赖**具体的物理设备**。

- 为实现这一特性，系统引入了**逻辑设备**与**物理设备**的概念：
	- 应用程序使用**逻辑设备名**请求某类设备。
	- 系统在运行时，必须将逻辑设备名**映射为实际的物理设备名**。

- 使用**逻辑设备名**的优势在于:
	- ① 提高**设备分配的灵活性**。
	- ②易于实现 **I/O 重定向**。
		- I/O 重定向：是指**用于I/O 操作的设备可以更换**(重定向)，而**不必修改应用程序**。

- 为实现设备独立性。需在设备驱动程序之上设置一层**设备独立性软件**。
- 设备独立性软件的**主要功能**包括以下两个方面：
	- ①**执行所有设备的公共操作**。包括：
		- **设备的分配与回收**。
		- 逻辑设备名到物理设备名的映射。
		- 设备保护(禁止用户直接访问硬件)。
		- **缓冲管理**。
		- 差错控制。
		- 提供**统一大小的逻辑块**，以**屏蔽**不同设备在信息交换单位和传输速率上的**差异**。
	- ② 向用户层(或文件系统)**提供统一的接口**。

- 通过**这一层抽象**，无论底层设备类型如何，应用程序均可**使用统一的系统调用(如 read/write)进行访问**，显著增强了系统的**可移植性**与**可维护性**。

## 3. 设备驱动程序
- 设备驱动程序**与硬件直接相关**，**每类设备都需要配置一个专用的驱动程序**。
	- 由于不同设备的内部硬件特性不同，内部具体细节只有厂家知道，因此**设备驱动程序需要由厂家提供**。
	- **跟硬件直接相关的操作**，找它就对了。

- 它是**I/O系统**与**设备控制器（即I/O接口）** 之间的通信桥梁，向上层**提供统一的操作接口**，屏蔽不同设备控制器的差异。

- 设备驱动程序的**主要任务**：
	- 接收上层软件(如**设备独立性层**)发出的**抽象 I/O 请求**(例如 read 或 write **命令**) 。
	- 然后，将其**转换为设备控制器能够识别的具体指令**，启动设备执行相应操作，并将设备控制器返回的状态信息或数据传递回上层。

- 此外，设备驱动程序还负责**设备的初始化、状态维护、错误处理**以及**与中断处理的配合**，通过封装底层硬件细节，使上层软件**无须了解设备的具体实现**，即可**使用统一接口访问各类I/O设备**。

- 设备驱动程序**工作流程**：
	- 1) **将抽象请求转换为具体操作**。
		- 上层请求通常是**逻辑性的**(如“读取逻辑块5”)，而**设备控制器**只能处理**物理操作**。
		- 因此，设备驱动程序根据设备特性，**将逻辑地址转换为物理参数**。
			- 例如， **磁盘驱动程序**会将**逻辑扇区号**转换为**柱面号、盘面号和扇区号**。
	- 2) **校验请求的合法性**。
		- 设备驱动程序**检查操作是否允许**，若请求非法，则向上层**返回错误**。
		- 例如，禁止从只写设备(如打印机) 读取数据，或向以只读方式打开的设备写入。
	- 3) **检查设备状态**。
		- 在启动 I/O 前，设备驱动程序读取**I/O接口的状态寄存器**，以确认设备是否就绪。
		- 例如，**写操作**要求设备处于“**接收就绪**”状态；若未就绪，则进程需要等待。
	- 4) **传递参数**。
		- 设备就绪后，**设备驱动程序**向控制器的**相应寄存器写入**命令、数据缓冲区地址、 传输长度等**参数**。
		- 例如，CPU启动设备驱动程序，**初始化DMA控制器的参数**。
	- 5) **启动设备并处理后续**。
		- 参数设置完成后，设备驱动程序**向命令寄存器发送启动信号**，设备开始工作。
			- 在多道程序系统中，**当前进程随即被阻塞**，CPU 转去**执行其他就绪进程**，实现与I/O设备的并行。
			- 设备**完成操作**并发出中断后，由**中断处理程序将其唤醒**，将其放入就绪队列。

## 4. 中断处理程序
- ![[第五章 5.1 IO软件层次结构 中断过程.png]]
- 上图中的“中断服务程序”即“**中断处理程序**”，**下半部分**的过程就是**由中断处理程序完成的**。
- 中断服务程序**汇编代码**（伪代码）如下：
```
; 前提：进入此入口前，硬件“中断隐指令”已自动完成：
;   1. 关中断 (IF = 0)
;   2. 保存断点 (PC/IP、CS、FLAGS 压入系统内核栈)
;   3. 中断向量寻址 (将 PC 指向本例的 ISR_Handler 入口)

ISR_Handler:
    ; 【步骤 4】：保存现场和中断屏蔽字
    ; (1) 保存通用寄存器（现场）
    PUSH AX
    PUSH BX
    PUSH CX
    PUSH DX

    ; (2) 读取并保存旧中断屏蔽字
    IN   AL, MASK_REG_PORT      ; 从中断控制器(如8259A)的屏蔽寄存器读出旧屏蔽字
    PUSH AX                     ; 将旧屏蔽字压栈保存

    ; (3) 设置当前中断对应的新屏蔽字
    MOV  AL, NEW_MASK_VALUE     ; 构造新屏蔽字（同级及更低优先级屏蔽位置 1）
    OUT  MASK_REG_PORT, AL      ; 写入屏蔽寄存器，阻止同级或低级中断

    ; 【步骤 5】：开中断
    STI                         ; CPU 开中断指令 (Set Interrupt Flag, IF=1)
                                ; 此时更高优先级的中断可以打断当前程序（支持嵌套）

    ; 【步骤 6】：执行中断服务程序主体
    CALL Device_Service_Body    ; 执行具体的设备 I/O 传输、数据读写或业务逻辑

    ; 【步骤 7】：关中断
    CLI                         ; 关中断 (Clear Interrupt Flag, IF=0)
                                ; 保护接下来的“恢复现场”阶段不被任何中断打断

    ; 【步骤 8】：恢复现场和中断屏蔽字
    ; (1) 恢复旧中断屏蔽字
    POP  AX                     ; 从栈中弹出旧屏蔽字
    OUT  MASK_REG_PORT, AL      ; 写回屏蔽寄存器，恢复先前的屏蔽状态

    ; (2) 恢复通用寄存器（现场）
    POP  DX
    POP  CX
    POP  BX
    POP  AX

    ; 【步骤 9 & 10】：开中断 与 中断返回
    ; 现代体系结构中，一条硬件中断返回指令 (IRET) 原子化完成两件事：
    ; 从栈中自动弹出并恢复原断点(PC/CS)与状态寄存器(FLAGS/PSW)。
    ; 原 FLAGS 中保存着进入中断前的开中断标志(IF)，随 IRET 恢复而自动“开中断”。
    IRET

```
- 当I/O 操作完成时，**设备控制器**发出**中断信号**。
- CPU 在**执行完当前指令后**响应中断，暂停当前进程，转去执行相应的**中断处理程序**。处理完毕后，再恢复原进程执行。

- 整个**中断**过程如下：
	- 1) 检测并响应中断（硬件）
		- 设备完成**一个数据单位(如字符或数据块)传输**后，其控制器发出**中断请求**。
		- CPU 在**每个指令周期的末尾**检测中断信号，若当前**满足响应条件**，则硬件自动暂停当前进程，转入中断响应。
	- 2) 硬件**保存断点与状态**（硬件隐指令）
		- 响应中断时，先**关中断**。
		- 硬件电路自动将程序计数器（PC/断点）和程序状态字（PSW）压入**系统内核栈/中断栈**，以确保返回时能精准回到被中断位置。
	- 3) **中断寻址**并转入中断处理程序（硬件隐指令）
		- 硬件根据中断向量号查询中断向量表，获取对应中断处理程序的入口地址并送入 PC，完成向中断软件代码的跳转。
	- 4) **保护通用寄存器现场**与**执行中断处理**（软件：中断处理程序）
		- 保存现场：中断处理程序正式接管 CPU，其**前导指令**将接下来需要用到的 CPU 通用寄存器（以及中断屏蔽字）**压栈保存**。
		- 处理中断：执行**设备具体的 I/O 服务主体**，读取设备控制器的状态寄存器检测设备状态；
			- 若正常，在设备数据缓冲寄存器和内存缓冲区之间传输数据；
			- 若异常，执行错误处理逻辑。
	- 5) 恢复现场并中断返回（软件 + 硬件协同）
		- 软件恢复：中断处理程序收尾，**从栈中弹出并恢复先前保存的通用寄存器**（和**旧屏蔽字**）
		- 硬件返回：执行**中断返回指令**（如 `IRET`），**硬件自动从栈中恢复原 PSW 和断点 PC**，CPU 无缝切换回原被中断进程继续执行。


- 为确保上述流程可靠运行，操作系统还需**对中断处理程序本身进行管理**，**中断处理程序的设计**可分为3个部分：①注册中断；②处理中断；③注销中断。
	- 1) **注册中断**。
		- **设备驱动程序初始化时**，需要**向内核注册中断号及其处理函数入口地址**，以建立硬件中断信号与服务代码之间的映射，确保中断发生时内核能准确调用相应处理例程。
	- 2) **处理中断**。
		- 中断处理程序的典型流程：
			- ① **确认中断是否由本设备产生**。
			- ② 清除**设备控制器中的中断标志**，防止重复触发。
			- ③ 执行必要的**硬件操作**，如读写数据。
		- 由于运行在中断上下文中，**处理程序必须快速、非阻塞**，不得调用可能引起进程睡眠或调度的函数。
	- 3) **注销中断**。
		- 当**设备驱动程序被卸载**或**设备停用**时，需要**注销其中断处理程序**以释放资源。
		- 若该中断请求线为独占，则注销后**内核立即禁用该线**。
		- 若该中断请求线为共享，则仅移除本设备的处理例程，该中断线需要等到所有关联设备均注销后，才会被最终禁用。
