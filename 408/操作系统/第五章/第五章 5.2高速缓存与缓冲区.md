
## 磁盘高速缓存(Disk Cache)
- 操作系统采用**磁盘高速缓存技术**以**提高磁盘I/O性能**，访问高速缓存中的数据比直接读写磁盘更高效。

- **磁盘高速缓存**不同于通常意义下的位于 CPU 与主存之间的硬件高速缓存，而是指**利用内存中的存储空间暂存从磁盘读取的盘块数据**。
	- 这些数据在逻辑上是磁盘内容的副本，物理上则**驻留在内存中**。

- **磁盘高速缓存**在内存中有**两种组织形式**：
	- 一种是**在内存中开辟固定大小的专用缓存区**。
	- 另一种是**将系统空闲内存作为动态缓冲池**，供请求分页系统和磁盘I/O 子系统共享使用。

## 缓冲区(Buffer)
- 在I/O系统中，引入缓冲区的**主要目的**如下:
	- 1) 缓和CPU与I/O设备间**速度不匹配的矛盾**。（⭐）
		- 生动例证（激光打印机打印）：
		    - CPU 运算速度极快，微秒级就能生成一份数百页的文档数据；而机械打印机吞吐极慢，每秒只能印几页。
		    - **引入内存打印缓冲区后，CPU 花几十毫秒把数据全部“倾倒”进缓冲区即可脱身去干别的事**；打印机再按自身的物理慢速慢慢从中提取数据打印。若无缓冲，CPU 必须被活活“钉死”在原地，等待打印机机械喷墨逐字走纸。
	- 2) 减少对CPU的**中断频率**，放宽对中断响应时间的限制。
		- 生动例证（串口传输 / 键盘输入 vs 高速网卡）：
		    - **如果硬件没有缓冲机制，外设每收到 1 个字节 就必须向 CPU 报送一次中断**。在千兆网卡或高速串口下，CPU 每秒会被轰炸数百万次，光是保存/恢复上下文就足以导致系统瘫痪（中断活锁），且 CPU 若晚响应几十纳秒，该字节就会被下一个到来的数据直接冲刷覆盖。
		    - **引入缓冲区后，外设每攒满一个数据块（如 4KB 或 64 字节）才向 CPU 发一次中断**，不仅将中断频率骤降数千倍，也给 CPU 留出了宽裕的调度响应窗口。
	- 3) 解决基本数据单元大小(**数据粒度**)**不匹配**的问题。
		- 生动例证（逐字符写入 vs 磁盘块读写）：
		    - 应用程序在逻辑上常以 1 个字符/字节（Byte） 为粒度操作数据（例如 C 语言的 `fputc('A', fp)`）；但底层磁盘或 SSD 的硬件物理读写必须以 “扇区/块（Block，如 4KB）” 为最小原子单位。
		    - 缓冲区充当了“粒度转换器”：**程序写入的单个字符先在内存缓冲区内累加**，等攒齐 4096 个字节（满 4KB）后，操作系统再调用底层驱动**一次性整块写入磁盘**。
	- 4) 提高CPU与I/O设备之间的**并行性**。（⭐）
		- 生动例证（在线视频“边下边播” / 双缓冲流水线）：
		    - 播放高清电影时，CPU 正在全速解码并渲染当前第 1 秒的画面（占用工作区进行计算 C）；与此同时，网卡利用 DMA 正在将**下一秒**的视频码流静默拉入**另一个系统缓冲区**中（输入传输 T）。
		    - 缓冲区的存在彻底**解耦了生产者与消费者**，**实现了“CPU 计算”与“设备传输”在时间轴上的重叠并行**，画面无需停顿等待网络包。

- 对于4)，**双缓冲/多缓冲/环形缓冲**通过将读、写操作隔离在不同的物理/逻辑缓冲区中，有效**避免了生产者与消费者对同一内存区域的读写冲突**，实现了**读写并发**。

- 缓冲区的**实现方法**包括：
	- 1) 采用**硬件缓冲器**，但由于**成本较高**，除一些关键部位外一般不采用。
	- 2) **利用内存作为缓冲区**，本节要介绍的正是**由内存组成的缓冲区**。

- 根据系统设置的**缓冲区数量**，缓冲技术可分为单缓冲、双缓冲、循环缓冲、缓冲池。

### 处理每块数据所需时间
- **数学渐进定义**：
    设系统连续处理 $n$ 块相同规模的数据，系统从初始启动至第 $n$ 块数据彻底处理完成的**总耗时**为 $T(n)$，则“**处理每块数据所需的时间**”（$\overline{T}$）定义为**数据规模趋于无穷大时的渐进平均耗时**：
    $$\overline{T} = \lim_{n \to \infty} \frac{T(n)}{n}$$
- 其中，$T(n) = (T + M + C) + (n - 1) × 流水线周期t$
- $n \to \infty$时，$\overline{T} = 流水线周期t$

- **物理与体系结构定义（流水线稳态节拍）**：
    指在流水线消除初始建立（冷启动）与排空等边界效应后，进入**稳定运行状态**时，相邻两块连续数据**先后处理完成并产出的时间间隔**。

	- 仔细观察图中进入**平稳阶段后**的状态。
	- 方法① 找“**重复基元**”
		- 从 $M_1$结束到 $M_2$​ 结束
	- 方法② 从“**产出点**”看周期（**对应严格定义**）
		- 从$C_1$结束到$C_2$结束

### 1. 单缓冲
- 当用户进程发出 I/O 请求时，操作系统**在内存中为其分配一个缓冲区**，对于**块设备**，其大小通常为**一个数据块**；对于**字符设备**，其大小为**用户输入的一行数据**。
- ![[第五章 5.2高速缓存与缓冲区 单缓冲区.png]]
- 如图，在**块设备**输入过程中，假设设备将一块数据送入缓冲区的时间为**T**，操作系统将缓冲区数据传送到用户工作区的时间为**M**，CPU 处理该块数据的时间为**C**。

- **单缓冲特性**：
	- 若缓冲区**非空**，则不能往缓冲区写入数据。（**读写互斥**）
		- 因为单缓冲区是**共享资源**，设备与CPU对其访问必须**互斥**。
	- 对于块设备， 必须**等整块数据装满缓冲区后**，**才能将其传送到工作区**。

- 在单缓冲中，**设备向缓冲区写入数据的时间T可与CPU 处理前一块数据的时间C并行**。（⭐）
	- **T和C并行，T和M串行，M和C串行**。（⭐）

- ![[Pasted image 20260911215423.png]]

- **当T > C时**，设备向缓冲区填充数据的速度慢于CPU 处理数据的速度。
	- 此时，CPU 在完成当前数据块的处理后，必须**等待设备将下一块数据完整写入缓冲区**。
	- 只有缓冲区装满后，操作系统才能将该数据块从缓冲区传送到用户工作区。
	- **处理每块数据**平均所需的时间为 **T+M**。

- ![[Pasted image 20260911215437.png]]

- **当T < C**时，设备填充缓冲区的速度快于CPU 的处理速度。
	- 此时，缓冲区一旦装满，设备便**无法继续写入新数据**，必须**等待 CPU 完成对当前工作区数据的处理**。
	- 此后，操作系统才能将缓冲区中的数据移至工作区，从而**释放缓冲区空间**。
	- **处理每块数据**平均所需的时间为 **C+M**。
	
- 综上，单缓冲**处理每块数据所需的时间（即流水周期）** 为 $\max(T, C) + M$。


### 2. 双缓冲
- 为了**加快输入/输出速度**，**提高设备利用率**，引入了**双缓冲机制**(也称**缓冲对换**)。
	- 由于缓冲区是共享资源，**生产者与消费者在使用缓冲区时必须互斥**。如果消费者尚未取走缓冲区中的数据，**即使生产者又生产出新的数据，也无法将它送入缓冲区**，此时生产q者需要等待。
	- 如果为生产者与消费者设置了**两个缓冲区**，便能解决这一问题。

- ![[第五章 5.2高速缓存与缓冲区 双缓冲.png]]
- 如图所示，**当设备输入数据时，先将数据送入缓冲区 1；装满后，转向缓冲区2写入**。
- 此时，操作系统可从已满的缓冲区1中取出数据送入用户工作区，并由 CPU 进行处理。
- 当缓冲区1的数据处理完后，若缓冲区2已装满，则操作系统切换到从缓冲区2中取数据送入用户工作区，而设备又可以开始向缓冲区1写入新数据。
- 可见，双缓冲**显著提高了设备与CPU 的并行程度**。

- **基本耗时与两级流水线模型**：
    - 基本参数：
        - $T$：I/O 设备将一块数据输入到缓冲区的时间（I/O 耗时）。
        - $M$：操作系统将缓冲区数据传送到工作区的时间（内存搬移耗时）。
        - $C$：CPU 对工作区中的数据进行计算处理的时间（计算耗时）。
    - **关键特性**：
        - 系统的两个处理阶段为：**输入段（耗时 $T$）** 与 **消费段（传送+计算，串行耗时 $M + C$）**。
        - 设备向一个缓冲区写入（$T$）可与系统传送及处理另一个缓冲区的数据（$M + C$）**完全并行**。

- ![[Pasted image 20260912092733.png]]
- **情况一：$T > C + M$（I/O 受限型，瓶颈在设备）**：
    - 运行状态：
        - 设备视角：设备向空缓冲区装入数据耗时较长，装满当前缓冲区时，另一缓冲区的数据早已传送并处理完毕恢复为空闲，故**空缓冲区源源不断供应，设备可连续无缝工作**。
        - CPU 视角：处理完上一块数据后，下一块数据的输入尚未完成，**数据无法持续供应，CPU 必须等待设备输入装满**。
    - 稳态分析：
        - 假设某一时刻，缓冲区 1 为空、缓冲区 2 已满。系统从缓冲区 2 传送并处理数据（耗时 $C + M$），同时设备向缓冲区 1 写入新数据（耗时 $T$）。
        - 当缓冲区 2 处理完毕时，缓冲区 1 尚未写满，系统必须等待剩余的 $T - (C + M)$ 时间后才能进行下一块的切换与传送。
    - 核心结论：
        - **处理每块数据的平均时间为 $T$**（瓶颈在于设备输入）。

- ![[Pasted image 20260912092756.png]]
- **情况二：$T < C + M$（计算/传送受限型，瓶颈在 CPU + 传送）**：
    - 运行状态：
        - CPU 视角：设备输入极快，当 CPU 处理完当前数据时，下一块数据早已在缓冲区就绪，**数据源源不断供应，CPU 无须等待设备输入**。
        - 设备视角：设备迅速装满一个缓冲区后，另一个缓冲区的数据仍在传送或处理中尚未释放，**空缓冲区无法持续供应，设备必须挂起等待释放**。
    - 稳态分析：
        - 类似地，当缓冲区 1 为空、缓冲区 2 已满时，系统传送并处理缓冲区 2 的数据（耗时 $C + M$），设备向缓冲区 1 写入数据（耗时 $T$）。
        - 缓冲区 1 虽然很快装满，但必须等待缓冲区 2 的数据彻底处理完毕并清空后，系统才能切换至缓冲区 1 开始传送。
    - 核心结论：
        - **处理每块数据的平均时间为 $C + M$**（瓶颈在于传送与计算）。

- 综上，**双缓冲处理每块数据的平均时间**为：$$\max(T,\; C + M)$$

- 如果在实现**两台机器之间的通信**时**仅为它们设置了单缓冲区**，如图（a）所示，那么它们之间在任一时刻都只能实现**单方向**的数据传输。（半双工通信）
	- 例如，只允许把数据从A机传送到B机，或者从B机传送到A机，而**绝不允许双方同时向对方发送数据**。

- 在双机通信时，为了实现**双向数据传输**（**全双工通信**），必须**在两台机器中都设置两个缓冲区**，一个用作**发送**缓冲区，另一个用作**接收**缓冲区，如图（b）所示。

### 3.循环缓冲(环形缓冲区)
- 在双缓冲机制中，当**输入与输出速度基本匹配时**，能够取得较好的效果；但若**两者速率相差较大**，则双缓冲**难以充分发挥作用**。

- ![[第五章 5.2高速缓存与缓冲区 循环缓冲区.png]]
- 为此，可引入**多缓冲机制**，并**将多个缓冲区组织成循环缓冲区的形式**，多个**缓冲区的大小相同**。
	- 如图所示：灰色表示已装满数据的缓冲区，白色表示空缓冲区。

- 循环缓冲由**若干个大小相等的缓冲区**构成，每个缓冲区包含一个**链接指针**，指向**下一个缓冲区**，**最后一个缓冲区的指针**则指向**第一个缓冲区**，从而形成一个**循环队列（单循环链表）结构**。

- 系统需维护两个指针：**in指针 和 out指针**，其中：
	- **in指针** 指向**下一个待写入的空缓冲区**。
	- **out指针** 指向**下一个待读取的满缓冲区**。

- 输入进程和计算进程在运行过程中**分别推进 in 和 out 指针**，沿链接方向循环移动。
- 采用循环缓冲技术，可以实现**输入进程与计算进程的并行执行**。由于**两者的处理速度可能不一致**，在运行过程中可能出现以下**两种同步情形**：
	- 1) in 追赶上 out (称为**系统受计算限制**)。
		- 该情况表明**输入进程的写入速度快于计算进程的处理速度**，导致**所有缓冲区均被填满**，无空缓冲区可供继续写入。
		- 此时，**输入进程必须阻塞**，直至计算进程从某个缓冲区中取走数据，释放出一个空缓冲区，并唤醒输入进程。
	- 2) out 追赶上 in (称为**系统受 I/O 限制**)。
		- 表明**计算进程的处理速度快于输入进程的写入速度**，导致**所有缓冲区均为空**，无数据可供继续处理。
		- 此时，**计算进程必须阻塞**，直至输入进程向某个缓冲区写入数据，使其变为满缓冲区，并唤醒计算进程。

### 4. 缓冲池
- 前述**缓冲区**是**专门为特定的生产者与消费者设置的**，它们属于**专用缓冲**。
- 当**系统较大**时， 应该有许多**循环缓冲**，但这不仅要**消耗大量的内存空间**，而且**缓冲区利用率不高**。

- 为了**提高缓冲区的利用率**，引入并广泛应用**既可用于输入、又可用于输出的（公用）缓冲池**， 该池中**设置了多个可供若干进程共享的缓冲区**。

- 缓冲池与缓冲区的**区别**在于：
	- **缓冲区**仅是**一组内存块的链表**。
	- **缓冲池**则是包含了**一个用于管理自身的数据结构**和**一组操作函数的管理机制**，用于**管理多个缓冲区**。

- 缓冲池是一种包含管理数据结构和操作函数的**软件机制**，用于统一管理多个缓冲区，并支持多进程共享使用。

- 缓冲池由系统统一管理的**供多个进程共享的一组缓冲区**构成。
- 根据**使用状态**，这些缓冲区被**组织为以下队列**：
	- ① **空缓冲队列emq**，由**空缓冲区**链接而成。
	- ② **输入队列inq**，由**装满输入数据的缓冲区**链接而成。
	- ③ **输出队列outq**，由**装满输出数据的缓冲区**链接而成。

-  注意：“输入”和“输出”是站在**计算机的视角**来看的。

- 缓冲池中的队列本身是临界资源，多个进程在访问一个队列时，既应互斥，又应同步。
- ![[第五章 5.2高速缓存与缓冲区 同步.png]]
	- Takebuf(type)：用于从type所指示的队列的**队首摘下一缓冲区**。
	- Addbuf(type， number)：用于将由参数number所指示的缓冲区B**挂在type队列上**。

-  ![[第五章 5.2高速缓存与缓冲区 缓冲池.png]]
- 在操作过程中，**缓冲区可动态扮演以下四种角色**：
	- ① 收容输入缓冲区 (hin)，用于**暂存输入**数据。
	- ② 提取输入缓冲 区(sin)，用于**读取输入**数据。
	- ③ 收容输出缓冲区(hout)，用于**暂存输出**数据。
	- ④ 提取输出缓冲区(sout)，用于**读取输出**数据。

- 缓冲池可以工作在如下**4种工作方式**下：
	- （1）**收容输入**。
		- 输入进程可调用Getbuf (emq)过程，从**空缓冲区队列emq**的队首摘下一空缓冲区，并把它作为**收容输入工作缓冲区hin**。
		- 然后，把数据输入其中，装满后再调用Putbuf(inq，hin)过程，将它挂在**输入队列inq**上。
	- （2）**提取输入**。
		- 计算进程可调用Getbuf (inq)过程，从**输入队列inq**的队首取得一缓冲区， 并将它作为**提取输入工作缓冲区sin**，计算进程从中提取数据。
		- 计算进程用完该数据后，再调用 Putbuf(emq，sin)过程，将它挂到**空缓冲区队列emq**上。
	- （3）**收容输出**。
		- 计算进程可调用Getbuf (emq)过程，从**空缓冲区队列emq**的队首取得一空缓冲区，并将它作为**收容输出工作缓冲区hout**。
			- 当其中装满输出数据后，再调用Putbuf (outq， hout)过程，将它挂在**输出队列outq**末尾。
	- （4）**提取输出**。
		- 输出进程可调用Getbuf (outq)过程，从**输出队列outq**的队首取得一装满输出数据的缓冲区，并将它作为**提取输出工作缓冲区sout**。
		- 在数据提取完后，再调用Putbuf(emq，sout) 过程，将它挂在**空缓冲区队列emq**末尾。

- 对于循环缓冲和缓冲池，本节仅介绍其**工作机制**，**不涉及时间性能的定量分析**。
- 而对于**单缓冲和双缓冲**，只要**依据前述模型进行分析（画甘特图）**，即可**求解任意场景下处理每块数据所需的时间**。


## 缓存与缓冲的对比
- 在I/O 系统中，**缓存**(Cache)是一种**利用高速存储介质保存慢速设备数据副本的机制**， 其访问速度远高于直接访问慢速设备。

- 现代计算机系统中有**多种类型的缓存**，如 CPU缓存、**磁盘缓存**、光驱缓存等。访问缓存副本比访问其原版更加有效。

- 缓存和缓冲的区别：
	- **缓冲**可以保存数据项的**唯一的现有版本**。
	- 而根据定义，**缓存**只提供一个**位于其他地方的数据项的更快存储副本**。

- ![[第五章 5.2高速缓存与缓冲区 缓冲与缓存.png]]

- 虽然缓冲（Buffer）与缓存（Cache）的设计初衷不同，但 OS 常将其合二为一（即缓冲区缓存 Buffer Cache，**缓冲区可用于缓存**），兼具**双重效能**：
	- 作为**缓存（Cache）**——“以空间换时间，靠复用提速”：
	    - **收到 I/O 请求先查内存**，若命中则直接读写，避免或延迟实际磁盘 I/O。
	    - 支持跨进程数据共享，加速高频热点文件的重读。
	- 作为**缓冲（Buffer）**——“缓和速度差距，靠聚合优化”：
	    - 保证了数据写入的“**复制语义**”（**将数据写入缓冲区后应用即可返回**，**无需干等落盘**）。
		    - “复制语义”：当应用程序调用 `write()` 等系统调用返回后，操作系统必须保证：**写到磁盘上的数据，绝对是调用发生那一瞬间的数据快照**；应用程序随后对该内存区的任何修改或释放，都绝不会破坏这次写入。
	    - 允许写操作暂存数秒，汇聚零碎写入为批量传输，便于磁盘调度算法合并与重排 I/O 请求。
