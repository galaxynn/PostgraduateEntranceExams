- 前面介绍的查找方法均适用于**存储在计算机内存中较小的文件**，统称为**内查找法**。
- 若文件很大且存放于**外存**进行查找时，这些查找方法就不适用了。
- 内查找法都以节点为单位进行查找，这样需要**反复地进行内、外存的交换**，是很费时的。
- 1970年，鲁道夫·拜尔（R.Bayer）和 E·麦克雷特（E.Mccreight）提出了一种**适用于外查找的平衡多叉树**——**B−树**，磁盘管理系统中的**目录管理**，以及数据库系统中的**索引组织**多数都采用**B−树**这种数据结构。

## B树的定义
- B树的**阶数**，即**叉数**。

- B树是一棵**多路平衡查找树**。**每个结点的平衡因子均为0**。

- $k$个**关键字**，对应$k+1$棵**子树**。
- 一颗**m阶B树**或为**空树**，或为满足以下特性的**m叉树**（$m\ge2$）：
	1. <u>每个结点</u>**最多有m棵子树**（即**最多**包含**m-1**个关键字）。（由**m叉树**的**定义**决定的）。
	2. 若**根节点不是叶结点**，则**最少**有<u>2棵子树</u>（即根节点**最少**包含1个关键字）。
	3. 除根节点外，所有**非叶结点**<u>最少</u>有$\lceil \frac{m}{2} \rceil$棵子树（即**最少**包含$\lceil \frac{m}{2} \rceil－1$个关键字）。
	4. 每个**非叶结点**的结构
		-  ![[第七章 B树 结构.png]]
		- 其中，
		- $n$为该结点中**关键字**的个数(**最多m-1个**)
		- $K_i$为**关键字**，且满足$K_1<K_2<\dots<K_n$
		- $P_i$为指向**子树根节点**的指针。指针$P_{i-1}$所指子树中所有关键字均**小于**$K_i$，指针$P_i$所指子树中所有关键字均**大于**$K_i$，小于$K_{i+1}$。
		- 从上述定义可以看出，对任一关键字$K_i$而言，$P_{i−1}$相当于指向其“左子树”，$P_{i}$相当于指向 其“右子树”。
	5. **所有叶结点**都出现在**同一层次**上，且不实际存储数据，通常称为**失败节点**。（作用类似于折半查找判定树中的**失败结点**，引入是为了便于分析B−树的查找性能）
		- 注：**统考真题**将B树的叶结点定义为**最底层终端结点**，**而非**外部叶结点(失败结点)。下面也这样定义。
- 要求：要对B树的定义**熟稔于心**。

- **判断是否为B树**的方法：
	- ① 判断**B树的阶数**：利用每个节点**最多包含的子树/关键字个数**。
	- ② 再验证**是否满足以上所有定义**。

- B−树具有**平衡、有序、多路**的特点。
- 基于以上定义，B树有以下**性质**：
	1. 每个结点**所有的子树的高度都相同**。（平衡）
	2. 树中**每个节点中的关键字都是有序的**，且关键字$K_i$“左子树”中的关键字均小于$K_i$， 而其“右子树”中的关键字均大于$K_i$。（有序）
	3. 除叶子节点外，有的节点中有一个关键字、两棵子树，有的节点中有两个关键字、3棵子树，这种4阶的B−树最多有3个关键字、4棵子树。（多路）
	4. 若B树中**一共**有$n$个**关键字**，则必有$n+1$个**外部叶结点**。
	5. 任意结点的子树个数＝关键字数＋1。
	6. 下层子树中的所有关键字均落在由上层结点关键字划分出的对应区间内（开区间）。
	7. 所有外部叶结点均位于**最底层**。

- B树各结点所包含子树、关键字个数归纳表：

|      | 子树个数                            | 关键字个数                               |
| ---- | ------------------------------- | ----------------------------------- |
| 根节点  | [2, m]                          | [1, m-1]                            |
| 非叶结点 | [$\lceil \frac{m}{2} \rceil$,m] | [$\lceil \frac{m}{2} \rceil-1$,m-1] |

## B树的查找
- 在B树上进行查找与二叉排序树**相似**，不同的是：B树中，每个结点都是多关键字的有序表。在该结点上所进行的是**多路分支决策**，**而非二路分支决策**。
- **B树**通常存储在**磁盘**上，要**依据想读取的目标结点的磁盘地址**，将<u>结点</u>**读入内存**，才可以在**该结点**的有序表中进行查找。

- B树的查找过程：
	1. 从**根节点**开始比较。
	2. 将结点从磁盘**读入内存**，在结点内的多关键字**有序表**中，使用**顺序查找或折半查找**：
		- 若找到目标关键字，**查找成功**。
		- 若未找到目标关键字，根据对应指针的信息，**定位下一个**要读入内存的结点，获取其**磁盘地址**，重复步骤2。若查找到**叶结点**，则说明树中不存在该关键字，**查找失败**。

## B树的高度
- B树通常存储在**磁盘**上，由B树的查找过程可知，因此所需**磁盘存取次数与树的高度成正比**。

- 注意：B树的高度**不包含**<u>最底层</u>**外部叶结点所处的那一层**。
- 假设存在一棵包含n个关键字，高度为h，阶数为m的B树：
	1. 最小高度情形：总关键字数固定时，每个结点的关键字数达到最大值时，B数的高度最小。对于m阶B树，每个结点最多包含m－1个关键字，最多有m棵子树。
		- 下面默认：1个结点有m-1个关键字，m棵子树。（最多）
		- 第一层：1个结点，m-1个关键字。有m棵子树。
		- 第二层：m个结点，m*(m-1)个关键字。有$m\times m = m^2$棵子树。
		- 第三层：$m^2$个结点，$m^2*(m-1)$个关键字。有$m\times m^2 =m^3$棵子树。
		- 第h层：$m^{h-1}$个结点，$m^{h-1}*(m-1)$个关键字。无子树。
		- 所以，高度为h的B树最多包含$n=(1+m+m^2+m^3+\dots+m^h-1)(m-1)=m^h-1$个关键字。
		- 由不等式$n \le m^h-1$，得$h \ge \log_m(n+1)$，则最小高度为$\log_m(n+1)$。

	2. 最大高度情形：总关键字数固定时，每个结点的关键字数达到最小值时，B数的高度最大。根节点最少1个关键字，非叶结点最少$\lceil \frac{m}{2} \rceil$个关键字。
		- 令 $d = \lceil \frac{m}{2} \rceil$
		- 下面默认：根节点有1个关键字，2棵子树；其余非叶结点有$d-1$个关键字，d棵子树。(最少)
		- 第一层：1个结点，1个关键字。有2棵子树。
		- 第二层：2个结点，2*(d-1)个关键字。有2d棵子树。
		- 第三层：2d个结点，2d*(d-1)个关键字。有$2d^2$棵子树。
		- 第h层：$2d^{h-2}$个结点。$2d^{h-2} \times (d-1)$个关键字。无子树。
		- 所以，高度为h的B树最少包含$n=1+(2+2d+2d^2+\dots+2d^{h-2})(d-1)=2d^{h-1}-1$个关键字。
		- 由不等式$n \ge 2d^{h-1}-1$，得$h \le \log_d(\frac{n+1}{2})+1$，则最大高度为$\log_d(\frac{n+1}{2})+1$。

- 综上所述，$\log_m(n+1) \le h \le \log_d(\frac{n+1}{2})+1$。

|         | 最小            | 最大                        |
| ------- | ------------- | ------------------------- |
| 关键字数$n$ | $2d^{h-1}-1$  | $m^h-1$                   |
| 高度$h$   | $\log_m(n+1)$ | $\log_d(\frac{n+1}{2})+1$ |


## B树的插入
- **多了**要**分裂**，**少了**要**合并**。
- B树的插入和BST的插入类似，不同之处在于：B树在插入后，要**判断被插入的结点是否仍然满足B树的定义**，若不满足，则需进行相关调整。

-<u> 新插入的关键字</u>**必定**在**最底层终端结点**处（注意：这里的终端结点，**不是**外部/失败结点）。

- B树插入的过程：
	1. **定位**。利用B树**查找算法**，沿着路径向下查找插入位置，最终会指向外部节点，但实际的插入位置是该失败结点的**父节点**，即最底层终端结点。
	2. **插入**。将关键字**插入**定位到的最底层终端结点，**插入之后**判断关键字个数是否超过m-1个。若不超过m-1，则**插入成功**，算法结束；否则，需要对该结点进行**分裂操作**（进入步骤3）。
	3. **分裂**。
		- 位置**从1开始计数**，从第$\lceil \frac{m}{2} \rceil$个位置处（记为**中间位置**）将该节点关键字序列**分成两半**。
		- 创建一个**新结点d**（假设由**指针p**指向）。
		- **左半部分**的关键字**保留在原结点**中，**右半部分**的关键字移至**新结点d**中。
		- **中间位置**的关键字**提升**，即**和指针p一起**和插入到原节点的**父节点**（由parent指针指向）。
			- 若父节点因插入该关键字而导致关键字个数大于m-1，则对父节点**递归地执行分裂操作**。
		- 这一过程可能**向上传递**至根节点，若**根节点也被分裂**，则B树**高度加1**。

## B树的删除
- B树的删除和二叉排序树的删除有着**相似的思想**，不同之处在于：B树在删除后，需要**判断整棵树是否仍满足B树的定义**。
- 若删除处于**非终端结点**的关键字，和二叉排序树删除一样，将其**转化为对终端结点关键字的删除**。

- B树的删除过程：
	1. 若删除的是处于**非终端结点**的关键字，用**其前驱或后继的值**，**替换**该关键字的值。然后再在相应**终端节点**处<u>删除其前驱或后继</u>，**转化**为了对**终端节点**关键字的删除。
		- 前驱：该关键字**左侧子树中最"右下"的元素**。（左子树的最大元素）
		- 后继：该关键字**右侧子树中最"左下"的元素**。（右子树的最小元素）
		- 实际上，与找中序序列前驱和后继类似。
	2. 若删除的是处于**终端节点**的关键字。
		- 若删除该关键字**后**，关键字数≥$\lceil \frac{m}{2} \rceil-1$（即删除**前**>$\lceil \frac{m}{2} \rceil$），则**直接删除**。
		- 若删除该关键字**后**，关键字数<$\lceil \frac{m}{2} \rceil-1$（即删除**前**≤$\lceil \frac{m}{2} \rceil$）：
			- <u>兄弟够借</u>：左/右兄弟结点的关键字个数≥$\lceil \frac{m}{2} \rceil$时，**将该关键字删除后**，根据**大小关系**，**调整**该结点、左/兄弟结点及父节点相应关键字，使其满足B树的定义。
				- 具体调整方法：父关键字**先下去填空**，兄弟关键字**再上来填空**。（本质是：看哪个兄弟够借，找两个前驱或两个后继，依次填充空位。）
			- <u>兄弟不够借，找父亲借</u>：左/右兄弟结点的关键字个数均为$\lceil \frac{m}{2} \rceil-1$时（不够借），**将该关键字删除后**，将**该节点**的剩余信息、**其中一个**<u>兄弟结点</u>以及<u>父节点中分隔它们的关键字</u>**合并**为一个**新节点**（先**将父关键字下移**后，再**一起合并**），并**保留**在该层，仍**作为其父节点的子树**。
				- 合并后，父结点中的关键字会减1，若父结点中关键字数不满足B树的定义，则需要**将父结点视为被删除结点**，**递归地进行以上判断和操作**。直到整棵树重新满足B树定义。
				- 若**父节点为根节点**，且关键字个数减少到0，则**直接将根节点删除**，合并后的新结点称为新根，B树的**高度减1**。
