- 插入排序这一大类中，有三种重要的排序算法：**直接插入排序**、**折半插入排序**、**希尔排序**。

- 插入排序的基本思想：每次将一个待排序记录，按其关键字大小**插入前面已经排好序的子序列中**，直到所有记录都插入完毕。

- 记待排序表为$L[0 \dots n-1]$。（下标从0开始。）
## 直接插入排序
- 特性：在待排序序列**接近正序**时，其时间效率可提升至$O(n)$。即算法更适用于**基本有序或数据量较小**的排序场景。
- 算法流程：
	1. 初始时，将$L[1]$视为一个长度为1的有序子序列。
	2. 从$L[2]$开始，依次将$L[2]$到$L[n]$插入前面的有序子序列中。
	3. 查找当前要插入元素$L[i]$在有序子序列$L[0 \dots i-1]$中的**插入位置**$k$，直接插入排序是从后往前比较，找第一个**大于**$L[i]$的元素的下标作为插入位置（从后往前找到第一个**大于等于**$L[i]$的元素的下标，则需要寻找的下标是它的后一个位置）。
	4. 将$L[k...i-1]$中的所有元素**依次后移**一个位置，腾出位置$k$。（注意：直接插入排序算法实际实现中，是**边比较边移动**的。）
	5. 将$L[i]$放入位置$k$。
- 时间复杂度：
	- 最坏情况（表中元素**完全逆序**）：$O(n^2)$
	- 最好情况（表中元素已**基本有序**）：$O(n)$
	- 平均情况：$O(n^2)$
- 空间复杂度：$O(1)$
- 稳定性：**稳定**。插入时总是从后往前比较，若比较到有关键字相等，找的是后一个位置，所以相同关键字的元素相对顺序不会改变。
- 适用性：适用于**顺序存储和链式存储**的线性表。链式存储时，无需移动元素，但时间复杂度一致。

### 某一元素所需比较次数的结论
- 可直接用，**好用**，但**不要数错了**。
- 在直接插入排序中，一个元素的比较次数，等于它在已排序部分产生的逆序对数，再加上一个 “是否非前缀最小” 的**修正量**（非最小则 +1，最小则 +0）。整个排序的比较次数，本质上由**初始序列的逆序程度**决定。

- 设该元素为 key，位于下标 i。令

$$
\text{inv}_i = \bigl|\{\,j \mid 0 \le j < i,\; a[j] > a[i] \,\}\bigr|
$$

- 即 key 与前面 i 个元素形成的**逆序对个数**（**前面比它大**的元素个数）。

- 若 key **不是**前 i+1 个元素中的**最小值**（即前面存在 $\le$ 它的元素），  
  则比较次数为：
  $$
  C_i = \text{inv}_i + 1
  $$

- 若 key **是**前 i+1 个元素中的**最小值**（前面所有元素都大于它），  
  则比较次数为：
  $$
  C_i = \text{inv}_i \quad(\text{此时 } \text{inv}_i = i)
  $$

> 直观解释：在**往前扫描**时，每个大于 key 的元素都会产生一次比较（并后移），  最后还会与第一个 $\le$ key 的元素比较一次（若存在），从而**多出 1 次比较**；  若扫描到**最左端**都不存在这样的元素，则**不再有额外比较**。

## 折半插入排序
- 在直接插入排序中，总是**边比较边移动**元素。
- **折半插入排序**将二者分离：先通过**折半查找**（只能是**顺序存储的线性表**）**确定插入位置**，再**统一移动**元素。
- 具体来说：
	1. 初始时，将$L[1]$视为一个长度为1的有序子序列。
	2. 从$L[2]$开始，依次将$L[2]$到$L[n]$插入前面的有序子序列中。
	3. 用**二分查找**，找到第一个**大于**$L[i]$的元素的下标$k$作为其**插入位置**。
	4. **统一**将$L[k\dots i-1]$后移一位。
	5. 将$L[i]$放入位置$k$。
- 主要区别：查找插入位置的方式不同。

- 时间复杂度：
	- 主要改进在于减少关键字的比较次数，但元素移动的次数并未减少，依然依赖初始序列的有序程度。
	- 最坏情况（表中元素**完全逆序**）：$O(n^2)$
	- 最好情况（表中元素已**基本有序**）：$O(n)$
	- 平均情况：$O(n^2)$
- 空间复杂度：$O(1)$
- 稳定性：**稳定**。找的是第一个**大于**$L[i]$的元素的下标$k$作为其插入位置。所以相同关键字的元素相对顺序不会改变。
- 适用性：仅适用于**顺序存储**的线性表。

## 希尔排序
- 希尔排序：基于**直接插入排序的特性**，对插入排序进行改进，也称为**缩小增量排序**。

- 基本思想：通过**逐步缩小增量**的方式，对表中**相隔一定距离的元素构成的子序列**进行**多次直接插入排序**，使整个表逐渐**趋于基本有序**，最终通过一趟完整的直接插入排序完成全局排序。

- 算法流程：
	1. 首先选取一个**小于n**的初始增量$d_1$，将待排序表**划分**为$d_1$个**相隔一定距离的子序列**（各子序列所含数据元素数量**不一定相等**）。
	2. 对各子序列**分别进行直接插入排序**。
	3. 依次取**更小**的增量$d_2, d_3, \dots$，**重复**分组与排序操作，直到增量$d$减为1。
	4. 当增量$d$减为**1**时，所有记录**属于同一子序列**，且序列**已高度有序**，执行最后一趟直接插入排序，即可快速获得最终结果。
	5. 通常取$d_1=n/2，d_{i+1}=d_i/2$（希尔的建议。）（下取整。）

- 时间复杂度：（取决于所选增量序列，尚无定论。）
	- 最坏情况（表中元素完全逆序）：$O(n^2)$
	- 最好情况（表中元素已基本有序）：$O(n\log n)$
	- 平均情况：$O(n^{1.3})$（n在**常见范围**时。）
- 空间复杂度：$O(1)$
- 稳定性：**不稳定**。因为相同关键字可能会被**划分到不同子序列**中，从而**改变它们的相对位置**。
- 适用性：仅适用于**顺序存储**的线性表。（利用增量$d$进行**分组**，需要**随机存取**的特性。）
