### 44题 Cache/ 数组遍历的Cache命中率计算
- 状态：
	- **物理地址划分遗忘**，导致**做题速度慢**，暂时跳过了最后一问，**后面回来已经没时间了**。
	- 第二问**计算错误**：偏移量**忘记加上首地址**就出结果了。
	- 第三问：**时间不足**。

- **涉及知识点**：Cache物理地址划分，Cache的总容量计算，Cache行存放的内容，Cache行号计算，Cache命中率计算。

- 正确思路：
	- 由于主存分块，物理地址空间被**逻辑划分**为{主存块号 + 块内偏移}。
	- Cache采用**直接映射**，**每个主存块对应唯一Cache行**，对应的Cache行号 = 主存块号 % Cache总行数(通常是2的c次幂)，则**主存块号的低c位为Cache行号**，这是由**公式决定的**。
	- 物理地址空间进一步被**逻辑划分**为{Tag标记 + **Cache行号** + 块内偏移}，Tag标记位数 = 物理地址总位数 - 块内偏移位数 - Cache行号位数。
	- **涉及Cache的题，写题前先把以上信息都计算出来**。
	- **需要记忆：直接映射 -> 有Cache行号**。
	- **计算某数据/指令所在Cache行号**需要**先知道主存块号**，主存块号 = $\lfloor \frac{数据/指令的主存字节地址}{块大小(B)}\rfloor$，再套用上面那个公式即可，小心计算。
	- Cache总容量 = （控制位位数 + 数据位位数）× Cache行数
	- **数组遍历的Cache命中率计算**是需要**仔细分析**的。
	- 按行访问：
		- **int变量**角度：一个Cache行最多存放16个int变量。数组一行有256个int变量，至少需要256 / 16 = 16行Cache才能**完整存放数组的一行元素**，因此，每访问16个int，就会缺失1次，总共缺失 256 × 256 / 16 次，然后计算缺失率，再计算命中率。
		- **主存块**角度：每访问1个主存块，Cache就会缺失1次，数组共占用256×256×4 / 64 块，则共缺失这么多次，然后计算缺失率，再计算命中率。
