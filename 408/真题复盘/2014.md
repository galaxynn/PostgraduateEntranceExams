## 第3题 错 考点：循环队列队空队满
- 题目：![[2014 3.png]]
- 错因/我的问题：
	- 两端均可进行入队和出队操作，**误以为谁入队和谁出队都是 + 1**，导致**每个选项都不正确**。
		- **常规**的队尾入队、队头出队是 + 1。
		- 但是**队尾出队、队头入队是 - 1**。（记住）

- 知识点/思考：
	- **队尾操作**：  
		* 入队：`A[end2] = x; end2 = (end2 + 1) % M;`  
		* 出队：`end2 = (end2 - 1 + M) % M; x = A[end2];`  
	* **队头操作**：  
		* 出队：`x = A[end1]; end1 = (end1 + 1) % M;`
		* 入队：`end1 = (end1 - 1 + M) % M; A[end1] = x;`  
	 - <u>常规的</u>队尾入队、队头出队都是 + 1。
	 - **队尾出队、队头入队都是 - 1**。

- 下次怎么做： 
	- **记住上面两个点**，再**总结循环队列队空队满方法论**。

	- D. 在哈希表中查找一个关键字，需要**从哈希函数计算出的初始位置开始探测**，直到**找到该关键字或遇到空单元**。一旦形成“**堆积块**”，落在该区域附近的关键字都需要经过**更长的探查链**（更多的比较次数）才能定位。

## 第22题 遗忘 | 不确定 考点：程序中断方式/百分比
- 题目：![[2014 22.png]]
- 错因/我的问题：
	- **没意识到**： 400ns 是**定死的**，外设**不会等CPU**。

- 知识点/思考：
	- 用**时间**计算占比的核心方法：**画图**，再利用**一个周期内的占比 = 总占比**。
	- 这 400ns 是定死的（即中断请求的到达周期为 400ns），绝不是从处理完中断才开始计时的。
	- **外设产生请求的依据是自身速率**：  
		- 外部设备（如网卡、磁盘、传感器或 A/D 转换芯片）是在自己独立的硬件时钟驱动下工作的。**当它的数据缓冲区装满一个字（或一帧数据）时**，就会**向 CPU 发送一个中断请求**（IRQ）。
	* **外设不会等 CPU**：  
		* 外设“每 400ns 准备好一个数据并发出请求”，这个节拍是**外设自身的物理特性决定的**。它并**不知道、也不关心** CPU 是秒回、延迟 50ns 回、还是花了 100ns 才处理完。  
	* **数据丢失风险（也是题干给 50ns 的原因）**：  
		* 正因为外设是**定死每 400ns 发一次请求**，**如果 CPU 处理太慢，到下一个 400ns 时新数据到达，老数据就会被冲掉（溢出）**。题干中的“最长延迟时间 50ns”正是为了保证：  $$\text{延迟}(50\text{ns}) + \text{响应处理}(100\text{ns}) = 150\text{ns} < 400\text{ns}$$
		- 说明在下一个请求到来之前，CPU 肯定能把当前数据处理完，系统是**可靠**的。

- 下次怎么做：
	- 凡是遇到“某外设**每隔 T 发出一次请求**，每次处理耗时 t”，均默认：**时间周期 T 是硬性的、定死的**。
	- 外设不会等CPU，CPU没拿数据是它自己的事，就像**反正我已经把外卖送到并打电话给你了，你没拿外卖被偷是你自己的事**。
