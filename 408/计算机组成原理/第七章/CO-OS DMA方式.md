- **DMA 方式(Direct Memory Access)** 是一种**完全由硬件控制的数据传输方法**，它具有程序中断方式的优点，即**在数据准备阶段，CPU与外设可并行工作**。

- DMA 在**外设与内存之间**建立了一条**直接的数据通路**，使得**数据无须经过CPU传送**，仅在**传输开始前**（初始化）和**结束时**（发中断请求后处理）**才需要 CPU**，从而显著降低 CPU 在数据传输过程中的负担。
- 正因如此，该方式被称为**直接存储器存取**，并**避免了**保存与恢复 CPU 现场等复杂操作。
	-  所谓的“**直接数据通路**”： 指的是**逻辑逻辑数据流向**。数据从外设直接流向主存（或主存直接流向外设），中途**不需要把数据先搬进 CPU 的通用寄存器**（如 AX/EAX）周转，**并非拥有专用的物理线路**。

- DMA 特别适用于磁盘、显卡、声卡、网卡等**高速设备**的**大批量数据传输**，但其**硬件实现开销较高**。

- 在 DMA 方式中，**中断**的作用**仅限于处理故障和正常传输完成的通知**。
	- **中断**是**现代计算机必不可少的功能**。
	- 使用 DMA方式 ≠ 计算机没有中断功能。

## 1. DMA 方式的特点
- DMA 机制在主存与DMA 控制器之间**建立了一条直接的数据通路**。由于**数据传输不经过 CPU**，因此**无须中断现行程序**，从而**实现I/O 操作与CPU 计算的并行执行**。

- 注意：DMA方式**也会使进程进入阻塞态**，因为进程需要数据才能继续执行，而数据传输需要**等待DMA传输完成**。

- DMA方式的**主要特性**包括:
	- 1) **打破主存与CPU的固定关联**，主存既可被CPU访问，又**可被外设直接访问**。
	- 2) 在块数据传输过程中，主存地址的生成与传送字数的计数均**由硬件电路自动完成**。
	- 3) 主存中需**设置专用缓冲区**，以支持高效的数据交换。
	- 4) 支持**高速数据传输**，且**CPU与外设可并行工作**，显著提升系统效率。
	- 5) **传输开始前**需**由软件进行预处理**，**结束后**则**通过中断机制完成后处理**。

## 2. DMA 控制器的组成
- ![[CO-OS DMA方式 DMA数据通路.png]]
- 如图所示，在DMA方式中，**对数据传送过程进行控制的硬件**称为**DMA控制器**(**DMA接口**)。
	- 事实上，DMA控制器 ≠ DMA接口。
	- 在考研语境中，**直接把它们视为同一种硬件功能部件即可**，可理解为**DMA接口集成了DMA控制器**。（**中断接口**也是类似。）
		- 其中，DMA接口**是I/O接口的一种**，里面**包含I/O端口**。

- 当I/O设备需要进行**数据传送**时，通过**DMA控制器**向CPU提出 **DMA请求**，CPU响应后即**让出系统总线**，**由DMA控制器接管总线并执行数据传送**。

- DMA 请求包含**两级握手**：（⭐）
	- I/O 设备 向 DMA 控制器 发 **DMA 请求**（通知数据就绪）。
	- DMA 控制器 向 CPU 发 **总线请求**，申请总线控制权（通知让出总线），**有时也可称为DMA请求**。
		- **总线请求** 是 DMA 控制器（DMAC）**直接通过专用硬件控制线发给 CPU**（或总线仲裁器）的电平/脉冲信号。
		- 因此，总线请求**不需要中断**。（⭐）

- DMA控制器（**DMAC**）的**主要功能**如下：
	- 1) 接收外设发出的**DMA请求**，并向CPU发出**总线请求信号**。
	- 2) 在CPU发出**总线响应信号**后，DMA控制器**接管总线控制权**，进入**DMA操作周期**。
	- 3) 确定数据传送的**主存起始地址及长度**，并**自动更新**主存地址计数器和传送长度计数器。
	- 4) 指定数据在主存与外设间的**传送方向**，**发出读/写等控制信号**，完成数据传送。
	- 5) 在DMA操作结束后，**发出中断，向CPU报告传送完成**。

- ![[CO-OS DMA方式 DMAC.png]]
- 上图是一个**简单的DMA控制器**。
	- 1) **主存地址计数器**：存放**当前待传送数据的主存地址**。
		- 传送前，保存整批数据的**主存起始地址**。
		- 每传送一个字，其**内容自动加1**，直至该批数据传送完毕。
	- 2) **字计数器**：记录**当前待传送数据的剩余长度**。
		- 传送前，存入整批数据的**总字数**。
		- 每传送一个字，其**内容自动减1**，当**计数器为0时，表示传送结束**。
	- 3) **数据缓冲寄存器**：**暂存**每次传送的数据。
		- 通常，在**微观层面**，DMA 控制器与主存之间**以字为单位传送**，而**与外设之间**可能**以字节或字为单位**。（⭐）
		- 在**宏观层面**，DMA 传输的基本单位是**数据块**，CPU 只需在传输前初始化一次，**传输整块数据结束后**，DMAC 才会向 CPU 发出一次**中断请求**。（⭐）
	- 4) **DMA 请求触发器**：I/O 设备准备好数据时，向DMA控制器发出**DMA请求信号**，使其**置“1”**，由控制/状态逻辑向CPU发出**总线请求信号**。
	- 5) **控制/状态逻辑**：用于设定传送方向、更新传送参数，并协调 DMA 请求与CPU 响应信号。
	- 6) **中断机构**：当**一批**数据传送完毕后，**触发中断并向 CPU 发出中断请求**。

- 在DMA 传送过程中，**DMA 控制器接管系统总线**。
- 传送结束后，DMA控制器将**总线控制权**交还给 CPU，由 CPU 继续执行后续操作。
- 因此，**DMA 控制器必须具备控制系统总线的能力**。
	
## 3. DMA 的传送方式
- 由于 **DMA控制器和CPU共享主存**，所以可能出现**两者争用主存的现象**。
- 为使两者**协调使用主存**，DMA通常采用以下3种方式之一进行数据传送。

### 1) 停止CPU访存
- 一口气传完。
- 当I/O设备发出DMA请求时，DMA 控制器**向 CPU 发送停止信号**，**使 CPU 放弃总线控制权并暂停访存**，直至DMA**完成整块数据的传送**。
- 数据传送**结束后**，DMA 控制器**通知 CPU 恢复主存访问**，并**交还总线控制权**。
- ![[CO-OS DMA方式 停止CPU访存.png]]

- 优点：控制逻辑简单，适用于**数据传输速率很高的I/O设备**进行成组数据传送。
- 缺点：DMA访存期间，**CPU基本处于空闲状态**，**资源利用率较低**。
### 2) 周期挪用
- 周期指的是**存取周期/存储周期**。

- 对于**高速I/O设备**，若**不及时访存可能导致数据丢失**，因此其**访存请求具有较高优先级**。
- **周期挪用**允许I/O设备**挪用一个主存存储周期**，**传送完一个数据字后立即释放总线**，属于**单字传送方式**。（一次只能传一个字。）
- 当I/O设备发起DMA请求时，可能出现以下**三种情况**：
	- ① CPU**当前不在访存**，I/O请求无冲突，可**直接使用总线**。
	- ② CPU**正在访存**，则需**等待当前存储周期结束**，CPU再**释放总线控制权**。
	- ③ I/O与CPU**同时请求访存**，发生冲突，此时CPU**暂时放弃总线控制权**。

- ![[CO-OS DMA方式 周期挪用.png]]
- 优点：既满足了I/O数据传送需求，又**较好地发挥了CPU与主存的效率**。
- 缺点：每次挪用**均需申请并释放总线控制权**，带来一定**开销**。

### 3) DMA与CPU 交替访存
- 将**CPU工作周期划分为两个子周期**：一个供**CPU访存**，另一个供**DMA访存**。这样，**在每个CPU周期内，两者可以轮流访问主存**。
- 该方式仅适用于**主存存储周期 < CPU工作周期**的场景。
	- 例如，若CPU工作周期为1.2us，主存存储周期**小于0.6us**，则**可将其分为C1和C2两个子周期**，其中**C1专供DMA访存**，**C2专供CPU访存**。
	- 总线控制权通过C1和C2分时固定分配，**无须动态申请或释放**。
![[CO-OS DMA方式 交替访存.png]]
- 优点：**无须**总线控制权的申请与释放过程，**数据传送速率高**。
- 缺点：**硬件控制逻辑较为复杂**。

## 4. DMA的传送过程
- DMA 的**数据传送流程**分为**预处理**、**数据传送**和**后处理**三个阶段。
![[CO-OS DMA方式 DMA流程.png]]
* **(1) 预处理**
  * ① **设备驱动程序初始化与启动：**
    * **CPU 响应 I/O 系统调用，执行对应的设备驱动程序（处于内核态）**。
    * 驱动程序通过 I/O 指令（或内存映射 I/O）向 **DMA 控制器**的硬件寄存器写入：
	    -    **主存起始地址**（写入主存地址寄存器）
	    -    **传送数据量 / 字计数**（写入传送计数器）
	    -    **传送方向与控制字**（写入控制状态寄存器）
    * 驱动程序随后发出命令**启动外设**进行数据准备；
    * CPU 退出驱动程序，**转回继续执行其他进程/原程序**（实现 CPU 与外设的并行工作）。
  * ② **两级请求触发：**
    * 当外设完成数据准备（如输入缓冲区装满）后，向 **DMA 控制器**发出 **DMA 请求**；
    * DMA 控制器收到后，随即向 **CPU（或总线仲裁器）** 发出**总线请求**，申请**接管总线控制权**。

- (2) **数据传送**
	- DMA控制器一旦**获得总线控制权**，DMA 控制器便**通过硬件循环自动完成数据的输入或输出操作**，整个过程**无须 CPU 干预**。
		- 宏观层面，**一次 DMA传送以数据块为单位**。
		- 微观层面，在内存与外设之间每次**实际搬运**的数据大小是**一个字或字节**。
- (3) **后处理**
	- **数据块传送完成后**，DMA 控制器向CPU发出**中断请求**。CPU 响应后**执行中断服务程序**，进行**后处理工作**，如**校验数据完整性**，若出错则转入诊断程序等。
	
- 在DMA 方式下，**整个数据块的传送过程均由硬件完成**，CPU**仅在预处理阶段进行初始化**，**在后处理阶段响应中断**，因此用于I/O的开销极小。

- 假定计算机的主频为500MHz，CPI 为4，某外设的数据率为40MB/s， I/O 接口中的数据端口为32位，采用DMA方式，每次DMA 传送块大小为1000B，且DMA 预处理和后处理的总时钟周期数为500，则CPU 用于该外设 I/O 的时间占 CPU 总时间的百分比是多少？


## 5. DMA 方式和中断方式的区别
- DMA 方式和中断方式的**主要区别**如下：
	- ① 
		- 中断方式涉及**程序切换**，需**保存和恢复 CPU 现场**。
		- DMA 方式**不中断现行程序，无须保存现场**，除预处理和后处理外，完全不占用 CPU 资源。
	- ② 
		- 中断请求**只能在每条指令执行结束后被响应**。
		- DMA 请求可**在当前总线周期结束后立即获得响应**，无须等待指令完成。
		- 问“中断”响应时机 → 认准“**指令执行结束时**”（指令周期末）。
		- 问“DMA”响应时机 → 认准“存取周期 / 总线周期 / 当前流水段结束时”（周期挪用）。
			- 通常可认为 **存取周期 = 总线周期 = 流水段长度**
	- ③ 
		- 中断方式的**数据传送依赖 CPU 执行指令（软件）完成**。
		- DMA 方式则**由专用硬件直接在主存与外设间传送数据**，传输速率高，适用于**高速外设的成组数据传输**。
	- ④ CPU和DMA 控制器同时访问主存时，**DMA 请求的优先级通常更高**。
		- DMA的优先级**比任何外中断请求高**。
		- 优先级从高到低：
			- **异常（内中断）> DMA请求 > 不可屏蔽中断 > 可屏蔽中断**
	- ⑤ 中断具备处理异常事件的能力，而DMA仅用于大批量数据的高效传输。

| :----------------------------------- | :--------------------------------------------------------------------------------------------- | :--------------------------------------------------------------- |
| **程序查询方式**<br>(Programmed I/O)       | **极低速、突发性极低** 或 **专用/嵌入式专用设备**<br>• 早期低速打孔机、极低速传感器<br>• 实时性极强且必须立即拿到响应的专用测控接口（轮询效率反而高于中断上下文切换） | **极低速**<br>数据以**字 / 字节**为单位传输                                    |
