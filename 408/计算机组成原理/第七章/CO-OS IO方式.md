- 外设与主机之间的数据传送称为**输入/输出**，简称**I/O**。
- 主要有程序**直接控制、中断控制和DMA控制**3种**I/O数据传送控制方式**。
	- 其中前两种方式**高度依赖CPU执行程序指令**（软件）来完成控制。

- **软件实现**：由**CPU执行显式的机器指令序列**来完成逻辑功能。
- **硬件实现**：CPU少插手或不插手，**由电路自动完成**的逻辑功能。

## 程序查询方式（软件实现）
- 在程序查询方式中，**数据交换的控制**完全**由CPU通过执行程序实现**。
- 接口电路通常包含一个**数据缓冲寄存器**(数据端口)和一个**设备状态寄存器**(状态端口)。
- 在主机进行I/O操作时，首先**读取设备状态**，并据此决定是立即传送数据还是继续等待。

- ![[CO-OS IO方式 程序查询方式.png]]
- **程序查询方式的工作流程***（独占查询）如下:
	- ① CPU执行**初始化程序**，**预置传送参数**(如起始地址、数据量等)。
	- ② 向**I/O接口**发送命令字，**启动外设**，外设开始**向数据缓冲寄存器读/写数据**。
	- ③ **循环读取**外设**状态寄存器**，判断**外设是否读/写完成**。
	- ④ 若设备**未就绪**，则**继续查询**；若**就绪**，则**执行一次数据传送**（读或写）。
		- **一次数据传送的位数**等于**数据缓冲寄存器的位数**。
	- ⑤ **修改地址和计数器参数**。
	- ⑥ 判断**整个传送是否完成**，若未完成则返回步骤3，直至**计数器归零**。

- 根据**查询策略**的不同，程序查询方式可分为两类:
	- 1) **独占查询**。
		- **设备启动后**，CPU便**连续不断地查询其状态，直至操作完成**。(⭐)
		- 在此期间，**CPU无法执行其他任务**，处于**忙等待状态**，导致CPU与外设完全**串行工作**。
	- 2) **定时查询**。
		- **设备启动后**，CPU以固定时间间隔**周期性地查询外设状态**。
			- 注意：查询间隔即**查询周期**，指的是**两次查询之间间隔的时间**，**不等于**CPU第一次查询的时刻！（对于第一次启动时的定时，见下。）
		- 每次查询时，若**设备已就绪**，则**传送一个数据单元**，随后**返回用户程序继续执行**。
		- 查询间隔需**根据外设的数据传输速率合理设置**，以**避免数据丢失**。(⭐⭐)

- 为了正确完成这种查询，通常要**执行**如下**3类指令**：
	-  ① **测试指令**（Test）
	    - 作用：读接口状态字（测试 `Ready` 标志位）。
	- ② **传送指令**（Transfer）
	    - 作用：设备准备就绪时，执行 `IN` / `MOV` 将数据读到 CPU 寄存器并写入内存。
	- ③ **转移指令**（Jump/Branch）
	    - 作用：若未就绪，跳转回去继续查；若已就绪，跳过等待区直接执行传送。
	- 对应下面例题中的“每次查询操作执行10条指令”。

```
; 定时查询服务程序示例
1.  PUSH  R1             ; 保护现场（保存寄存器）
2.  PUSH  R2
3.  IN    AL, [STATUS]   ; 读接口状态寄存器（检查是否真的就绪/校验错误）
4.  TEST  AL, 01H        ; 测试 Ready 标志位
5.  JZ    EXIT           ; 未就绪则跳出（定时模式下一般已就绪）
6.  IN    EAX, [DATA]    ; “取数”
7.  MOV   [BUFFER], EAX  ; 将取出的 4B 存入内存用户缓冲区
8.  ADD   EDI, 4         ; 更新内存指针
9.  POP   R2             ; 恢复现场
10. POP   R1
    RET                  ; 返回主程序
```

- 程序查询方式的**优点**：**设计简单、硬件开销小**。
- 程序查询方式的**缺点**：CPU 需**耗费大量时间进行查询与等待**且**在同一时间段内只能与一台外设通信**，导致**CPU与外设串行工作**，效率很低。

- 例题：假设计算机主频为500MHz，CPI为4，某外设的数据传输速率为2MB/s，其I/O接口配备一个32位数据缓冲寄存器。采用定时查询方式，**每次查询操作执行10条指令**。问：CPU最多间隔多长时间查询一次，才能避免数据丢失？此时CPU用于该外设I/O的时间占总时间的百分比至少为多少？
	- **必须明确**：CPU间隔多长时间查询一次，指的是**两次查询之间间隔的时间**，即**查询周期**。
	- “查询操作” ≠ 单纯的“查看”：
		- 在程序查询方式的计算题中，“一次查询操作”默认指代“完成一次数据交互所必须执行的完整 I/O 例程”（包含了查状态、**取数**、存数这一整套流程）。
	- $$\text{I/O时间占比} = \frac{\text{每次查询花掉的时间}}{\text{两次查询之间的间隔时间}} \times 100\%$$
	- 该公式使用了**由局部推总体的思想**。

- 知识点补充：
	- 1. **定时器**允许将“**首次计数初值**”与“**自动重装载周期**”**独立配置**：初值用于消除软件启动开销，将第一次查询提前到 1.92μs 触发，**保证耗时 0.08μs 的查询取数操作恰好在 2.00μs 缓冲区写满的极限时刻完成**，防止首轮数据溢出。
	- 2. 首轮归零后，硬件电路自动将重装寄存器中的数值装入计数器，使**后续所有的查询触发严格锁定为 2.00μs 的恒定周期**，既与外设 2MB/s 产生 4B 数据的稳态物理速率完全匹配，也保证了题目所求的“查询间隔”在定义与数值上始终等于 2.00μs。

## 程序中断方式
### 1.程序中断的基本概念
- **程序中断**是指**在计算机执行程序的过程中**，当出现某些急需处理的**外部事件或内部异常**时，CPU**暂停当前程序的执行**，**转去处理该事件或异常**。处理完毕后，再**返回到原程序的断点处继续执行**。
- 中断技术最初被用于实现**主机与I/O设备之间的异步通信**。

- 中断响应：由**硬件**实现。
- 中断处理程序（如从I/O接口读取数据）：由**软件**实现。

- 随着计算机系统的发展，中断技术被赋予了多种重要功能，主要包括:
	- 实现**CPU与I/O设备的并行工作**。
	- 处理**硬件故障和软件异常**。
	- 支持**人机交互**(如键盘输入、鼠标点击)。
	- 支撑多道程序与分时操作系统的**进程切换**。
	- 满足实时系统对快速响应的需求。
	- 实现**用户程序向操作系统的切换**(如通过软中断或**系统调用**指令)。
	- 在多处理器系统中**协调各处理器间的通信与任务迁移**。

- ![[CO-OS IO方式 程序中断.png]]
- ![[CO-OS IO方式 程序中断方式.png]]

- 中断的**基本工作思想**：
	- 当前**进程发起I/O操作**时，会启动相应外设，并**主动进入阻塞状态**。
	- CPU随即**转而执行就绪队列中的另一进程**，实现**外设与CPU的并行工作**。
	- 外设完成数据准备后，**通过I/O接口主动向CPU发出中断请求**。
	- CPU响应后，暂停当前指令流，保存现场，并**转入中断服务程序**，完成**主机与外设之间的数据传送**。
	- 数据传送结束后，CPU可能会**唤醒被阻塞的进程**，使其进入**就绪**状态，之后**恢复被中断进程的现场**，并**返回断点处继续执行**。
	- 此后，外设与CPU**再次并行工作**。

- 例题：假设计算机主频为500MHz，CPI为4，某外设的数据传输速率为40MB/s，其I/O接口配备一个32位数据缓冲寄存器。在中断I/O方式下，若每次中断响应与中断处理共需至少400个时钟周期，则该外设能否采用中断I/O方式？为什么？

### 2. 程序中断的工作流程
- 在介绍中断的工作流程前，先理解几个**核心概念**。

- ![[CO-OS IO方式 中断控制器.png]]
- **中断控制器**：是**介于 CPU 和各类 I/O 接口之间**的**专用控制部件**。
	- 其核心功能是：**收集各设备的中断请求**，**完成优先级判优与排队**，并向 CPU 提供对应的中断向量（服务程序入口）。
	- 中断控制器不是中断接口。

- **中断请求信号**： 这个信号**直接连接到 CPU 的中断请求引脚**（如 `INTR`），用于在当前指令执行末尾**通知 CPU 存在中断请求**。
	- 只要**存在任意一个（或多个）未被屏蔽的中断请求**，就会产生最终的**中断请求信号**。

1. 登记与屏蔽：各外设经 IRQ 线**将请求记入中断请求寄存器**，并由**中断屏蔽字寄存器**过滤允许放行的请求。
2. 采样与响应：CPU 在每条指令执行结束前（中断周期）采样中断信号；若有请求，发出中断回答信号，以**启动中断查询**。
3. 判优与编码：判优电路从放行的请求中**选出优先级最高者**，由编码器**输出其中断类型号**（**中断源标识**）。
4. 寻址与执行：CPU 从**数据总线**接收**中断类型号**，找到对应的服务程序入口地址并跳转执行。
	- 中断服务程序开始执行，CPU 访问设备的控制/状态/数据寄存器时，设备硬件电路会检测到，因而**自动撤销中断请求**。


- (1)**中断请求**
	- **中断源**是指**能够向CPU发出中断请求的设备或事件**。
		- 一台计算机**允许多个中断源同时存在**，且各中断源发出请求的时间具有**随机性**。
		- 为**记录并区分不同的中断请求**，中断系统**为每个中断源设置一个中断请求标记触发器**：当其状态为“1”时，表示该中断源有中断请求。
		- 这些触发器可组成**中断请求标记寄存器**，该寄存器**可集中置于CPU内部**，也**可分散在各个中断源中**。
	- 通过**INTR 信号线**发出的是**可屏蔽中断**，通过**NMI 信号线**发出的是**不可屏蔽中断**。
		- **可屏蔽中断**的优先级较低，在**关中断状态下不被响应**。
		- **不可屏蔽中断**用于**处理紧急且关键的硬件事件**(如 电源掉电、总线错误等)，其**优先级最高**，且**不受中断允许标志的影响**（不受关中断的影响）。
		- 当CPU**状态标志寄存器**中的**中断允许位（IF位）为1时**，CPU处于“中断允许”状态或“**开中断**”状态，否则就是 “禁止中断”或“**关中断**”状态。

- (2)中断**响应**判优
	- **中断响应优先级**是指 CPU **响应**多个同时发生的中断请求的**先后顺序**。
	- 由于中断请求具有随机性，当**多个中断源同时提出请求时**，需通过**中断判优逻辑**确定**优先响应哪个中断源的请求**。
	- 实现：中断响应的判优通常由**硬件排队器**(或**中断查询程序**)实现。
		- 常见的**响应优先级**如下：
		- ① **不可屏蔽中断 > 可屏蔽中断**
		- ② 在I/O 传送类中断请求中，
			- **高速设备 > 低速设备**；**高速设备**填满/清空缓冲区所需时间极短，必须尽快响应以防溢出。
			- **输入设备 > 输出设备**；输入是被动接收，**输入设备**超时会导致**数据被覆盖丢失**。
			- 实时设备 > 普通设备。

	- 中断优先级包括**响应优先级**和**处理优先级**。
		- **响应**优先级**由硬件线路或查询顺序固定决定**，**不可动态更改**。 
		- **处理**优先级可通过**中断屏蔽技术动态调整**，以**支持多重中断(中断嵌套)**。

- (3)**中断响应的条件**
	- 即**CPU能检测到中断并响应的条件**。
	 - (1) CPU处于“**开中断**”状态。
		 - 即中断允许标志为“1”。
		 - 注：**异常和不可屏蔽中断不受此限制**。
	 - (2) 至少要有一个**未被屏蔽的中断请求**。
	 - (3) **当前指令刚执行完毕**，无更高优先级任务待处理。
		 - 注：异常可发生在**指令执行期间**，不受此限制。

- I/O设备的就绪时间是随机的，而 CPU 仅在**每条指令执行结束时统一采样**中断请求信号(前提是开中断)。
	- 因此， **CPU 响应I/O中断的时机总是发生在某条指令执行完成之后**。此处所述中断特指I/O 中断, **不包括异常**。
	- 注意：**不可屏蔽中断**也是在**指令执行完毕后才检测的**。

- (4)**中断响应的过程**（⭐）
	- 当CPU**同时满足上述3个条件时**，就**响应中断**，进入**中断响应周期**。
	- 在**中断周期**中，通过执行一条**中断隐指令**，完成以下3个操作。
		- **中断周期**里所做的**全部事情**，就是**硬件自动执行“中断隐指令”**。
	- 1) **关中断**。
		- CPU 响应中断后，首先**将中断允许标志置为“0”**，禁止响应任何**可屏蔽中断**(包括更高优先级者)，以**防止在保存断点和现场时被新中断打断**。（保证保存操作是**原子操作**，不可被打断。）
		- 否则，现场信息可能**不完整**，导致中断返回后无法正确恢复原程序的执行。
	- 2) 保存**断点**和**程序状态**。
		- 为保证中断返回后能正确恢复原程序执行，需将**程序计数器(PC)** 和**程序状态字(PSW)** 等关键现场信息保存至**操作系统的内核栈**或**专用寄存器**中。
			- x86 机器保存PC 和 PSW 到内存栈中；MIPS 机器没有PSW，只保存PC到特定寄存器中。
			- **若无特别说明，则默认含有PSW**。
		- 中断与异常断点的差异：
			- **中断**发生于**指令执行完成后**，断点为**下一条指令地址**。
			- **陷阱类异常**(如系统调用)在**指令成功执行后触发**，断点为**下一条指令地址**。
			- **故障类异常** (如缺页、除零异常)因**指令未完成**，处理后需**重新执行当前指令**，断点为**当前指令地址**。
	- 3) 识别中断源并**引出中断服务程序**。
		- 通过**识别中断源**，将对应**中断服务程序的入口地址送入程序计数器 PC**。
		- 识别方法主要有**硬件向量法**和**软件查询法**，本节主要讨论更常用的硬件向量中断法。

- (5) **向量中断**
	- **识别中断源**分为**向量中断**和**非向量中断**两类。非向量中断采用软件查询法，已在第5章介绍。
	- [[第五章 5.5异常和中断机制#异常和中断响应过程]
	- ![[CO-OS IO方式 中断向量表.png]]
	- 在向量中断中，**每个中断源被分配一个唯一的中断类型号**，该类型号对应一个**中断服务程序的入口地址**，此**地址**称为**中断向量**。
		- **中断向量的地址**和**中断服务程序的入口地址（中断向量）** 是两个不同的概念，注意**区分**。
			- **中断向量本身就是地址**。
			- 中断向量的地址，即**地址的地址**。
		- 如图所示，12H、13H、14H 是**中断向量地址**，200、300分别是打印机服务程序和显示器服务程序的入口地址（**中断向量**）。
	- 系统将所有中断向量**集中存放在内存的特定区域**，该区域称为**中断向量表**。
	- 向量中断的过程：
		- ① CPU 响应中断后，首先在中断响应阶段从**数据总线**获取该中断源的**中断类型号**，然后据此计算出对应**中断向量在中断向量表中的地址**（中断向量的地址，非中断向量）。
		- ② 接着**从中断向量表中读取该中断向量**，并**送入程序计 数器 PC**，从而转入对应的中断服务程序。
		- 这种基于中断向量表实现转移的方法称为**中断向量法**，**采用该方法的中断**即为**向量中断**。

- **中断请求和响应信号**通过**I/O总线的控制线**传输，而**中断类型号**则在**中断响应阶段**由中断控制器经**数据总线**提供给 CPU，用于**定位**中断向量表中的相应表项。


- (6)**中断的完整过程**
	- **中断完整过程**主要包括两个阶段：**中断响应**和**中断处理**。
		- **中断响应阶段**由**硬件**实现。
		- **中断处理阶段**则由**CPU执行中断服务程序来完成**，所以中断处理是由**软件**实现的。
		- 王道图中的“中断处理过程”指的是**广义的处理**。
	- ![[CO-OS IO方式 中断完整流程-王道.png]]
	-  ![[CO-OS IO方式 中断完整流程-唐.png]]
	- **中断完整流程**如下：
		- ① **关中断**。
			- 防止在保存关键信息过程中被新中断打断。
		- ② **保存断点和程序状态**。
			- 由硬件自动将断点和状态信息保存至栈或专用寄存器。
		- ③ **引出中断服务程序**。
			- 通过中断类型号**获取服务程序入口地址，并送入PC**。
		- 此处开始，以上是硬件，以下是软件。
		- ④ **保存现场和中断屏蔽字**。
			- 通过**软件指令**将**现场信息**和**中断屏蔽字**压入栈中，以便后续恢复。
				- **保存中断屏蔽字的原因**：中断屏蔽字通常在进入新的中断服务程序时由软件加载。每个中断服务程序都有自己的中断屏蔽字，修改前需要保存。
			- 现场信息是指CPU中**可能被中断服务程序修改且需恢复的寄存器内容**（如**通用寄存器**）。
		- ⑤ <font color="#4bacc6">开中断</font>。
			- 由开中断指令实现，**允许更高优先级的中断请求被响应，从而实现中断嵌套**。
			- <font color="#4f81bd">对于单重中断(不支持嵌套)，不需要这一步</font>。
		- ⑥ 执行**中断服务程序**。
		- ⑦ <font color="#4bacc6">关中断</font>。
			- 由关中断指令实现，**确保在恢复现场和中断屏蔽字的过程中不被中断**。
			- <font color="#4f81bd">对于单重中断(不支持嵌套)，不需要这一步</font>。
		- ⑧ **恢复现场和中断屏蔽字**。
			- 从栈中恢复寄存器内容及中断屏蔽状态。
		- ⑨ **开中断、中断返回**。
			- 中断服务程序的最后一条指令通常为中断返回指令，用于恢复断点现场并返回原程序继续执行。
		- 其中，①~③由中断隐指令(硬件自动)完成，称为**中断响应**；④~⑨由中断服务程序(软件)完成，称为**中断处理**。
		- 对于单重中断(不支持嵌套)，上述流程中省略(开中断)和⑦(关中断)即可。
		- 值得注意的是，**每次保存和恢复信息（断点、现场）前，必须处于关中断状态，确保是原子操作**。

## 3. 多重中断和中断屏蔽技术
- 在CPU执行**中断服务程序**的过程中，
	- 若**出现新的更高优先级中断请求**，而CPU**不予响应**，则称为**单重中断**。
	- 若CPU暂停当前中断服务程序，转去处理新中断，则称为多重中断(也称中断嵌套)，如图7.5(b)所示。
