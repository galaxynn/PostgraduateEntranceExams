- 核心做题假设
- 1. 单次必成：默认查询一次或中断一次，**必定能完整取走/送出一个单位的数据**。
- 2. 时序无冲突：默认**外设生产速度与 CPU 消费速度是无缝契合、流水线式平稳推进的**，绝对**不要脑补**“CPU 来不及取导致数据被冲掉”或者“外设停下来干等”的**异常**情况。

## 一、 核心解法：宏观“每秒时钟周期法”（通量归一法）

### 1. 解题通用数学模型
无论是**DMA方式**、**中断驱动方式**还是**程序定时查询方式**，只要题目考察“CPU 用于该设备的时间占比 或 CPU 占用率”，直接套用以下纯周期比值模型：

$$\text{CPU 占用率} = \frac{N_{\text{CPU 吃掉的时钟周期 / 秒}}}{N_{\text{CPU 总时钟周期 / 秒}}} \times 100\% = \frac{f_{\text{任务}} \times C_{\text{单次}}}{f_{\text{CPU}}} \times 100\%$$

- **分母 $f_{\text{CPU}}$（总供给盘子）**：
    - CPU 主频（如 $500\text{ MHz} \implies 5 \times 10^8$ 个周期/秒；$1\text{ GHz} \implies 10^9$ 个周期/秒）。
- **分子 $f_{\text{任务}} \times C_{\text{单次}}$（外设消耗总量）**：
    - **$f_{\text{任务}}$（1 秒内触发的任务频次）**：
        $$f_{\text{任务}} = \frac{\text{设备数据传输速率}}{\text{单次传输数据量（DBR大小/缓冲区大小）}}$$
        - 数据寄存器每装满一次，就要查询/中断一次。
    - **$C_{\text{单次}}$（单次任务耗费的 CPU 时钟周期数）**：
        - 若给指令数与 CPI：$C_{\text{单次}} = \text{指令数} \times \text{CPI}$；
        - 若直接给周期数：如“单次中断开销 1000 个时钟周期”；
        - 若给单次处理物理时间 $t$：$C_{\text{单次}} = t \times f_{\text{CPU}}$。

### 2. 为什么“每秒时钟周期法”具备降维打击的优势？

- **彻底抹除时间量纲，规避单位换算陷阱**：
    - 传统解法在 $\text{s}$、$\text{ms}$、$\mu\text{s}$、$\text{ns}$ 之间反复倒腾，小数点和负指数极易出错。
    - 此方法直接将分子、分母统一转化为**纯整数的“时钟周期数”**，数字直接对消，心算即可出结果。
- **规避微观并发时序的二义性与认知内耗**：
    - 不必纠结“外设准备数据的同时 CPU 是否在运行”、“查询耗时算不算在间隔内”等边界细节。
    - 基于**宏观守恒定律**：1 秒钟内系统总共要搬走多少字节、必须触发多少次处理，属于刚性工作总量，与微观交替顺序无关。
- **极高稳定性与做题心流**：
    - 考场作答只需**提取数据 $\to$ 算频次 $\to$ 比值对消**三步，30 秒内锁定标准答案。

## 二、 什么时候必须请出“甘特图（时间轴）法”？

虽然宏观通量法在求“比例”时无往不利，但在以下**涉及微观绝对时空关系、临界死线（Deadline）、流水线冲突**的三大场景下，必须使用甘特图（时序图）进行局部推演：

### 场景 1：求解“最长响应延迟时间 / 缓冲区溢出临界点”
- **典型问法**：*“外设发出中断请求后，CPU 最迟必须在多少时间/多少个时钟周期内予以响应？”*
- **必须画图的原因**：
    - 涉及到两个事件的**绝对时间差**：
        $$t_{\text{最大允许延迟}} = t_{\text{外设填满下一组数据的时间}} - t_{\text{CPU 读走当前数据的时间}}$$
    - 此时必须画出**外设双缓冲装填**与 **CPU 读操作**在时间轴上的重叠区间，才能找到数据被覆盖的前一刻临界点。

### 场景 2：指令流水线（Pipeline）冒险与停顿分析
- **典型问法**：*“某段包含数据相关/分支预测失败的指令序列，在流水线中执行需要多少个时钟周期？”*
- **必须画图的原因**：
    - 指令间存在空间（硬件功能部件）和时间（时钟节拍）的精细重叠与阻塞（Stall）。
    - 宏观 CPI 均值已失效，必须通过甘特图画出 `IF, ID, EX, MEM, WB` 阶段的推进和气泡填充。

### 场景 3：总线事务仲裁与周期挪用（DMA 突发 vs 周期窃取）
- **典型问法**：*“DMA 控制器与 CPU 发生访存冲突时，CPU 实际停顿了几个总线存取周期？”*
- **必须画图的原因**：
    - 考察的是 CPU 机器周期末尾的**总线控制权交接时序（如 HOLD / HLDA 握手信号）**。
    - 必须画出总线时钟脉冲，标明 CPU 何时释放总线、DMA 何时接管、何时交还。
