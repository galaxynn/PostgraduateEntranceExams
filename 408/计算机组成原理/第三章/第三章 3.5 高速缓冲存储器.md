
## Cache
- 背景：
	- 程序的转移概率通常较高，数据分布也较为离散，因此**单纯依赖并行主存系统来提升主存效率是有限的**。
	- 在 CPU 与主存速度**差距不断拉大**的背景下，为了**缓解存储墙问题**，利用**程序局部性原理**，用**少量高速 SRAM 作为 Cache**，以**较低成本**实现**接近高速存储器的平均访问性能**。
		- CPU 访问一次主存的时间可能需要几十甚至上百个 CPU 周期，**CPU 大部分时间都在等待数据**，形成严重的性能瓶颈，即所谓的“**存储墙**”。

- **高速缓存（Cache）** 具有比**主存更快的访问速度**，因此在CPU与主存之间设置Cache可以**缓解 CPU 与主存之间的速度不匹配**，**显著提升**存储系统的整体效率。

- Cache 由 **SRAM**组成，通常**集成在 CPU 内部**。　

## 程序访问的局部性原理
- **程序访问的局部性原理**为引入 Cache **提供了理论依据**，Cache的设计基于程序访问的局部性原理。

- 程序访问的局部性原理包括**时间局部性**和**空间局部性**。
	- **时间局部性**：一个**数据或指令**被访问后，不久**很可能再次被访问**（如循环）。
		- 这源于程序中存**在循环、重复调用的子程序**，以及**对同一数据的多次操作**。
		- **循环内涉及的指令和数据**都具有较好的时间局部性。
	- **空间局部性**：如果某**存储单元**被访问，则其**邻近的存储单元**在不久的将来很可能也被访问。**（如顺序执行、数组遍历）。
		- 这是因为**指令通常顺序存放并顺序执行**，而**数据（如数组）也往往以连续块的形式存储**。
		- 空间局部性对**单个变量**没有意义，对**数组、指令**才有意义。
		- **连续存放的指令、数据**具有较好的空间局部性。

- 高速缓冲技术正是利用局部性原理，**将程序当前活跃的部分数据**暂存于**容量小但速度极快的Cache 中**，使CPU的**多数访存操作**直接**在Cache 中完成**，从而**显著提升程序执行效率**。

## Cache的基本工作原理
- 为**便于Cache与主存交换信息**，（⭐⭐⭐）
	- **Cache和主存**<span style="background:rgba(74, 82, 199, 0.2)">都被划分</span>为**大小相等的块**。
	- **Cache块**（也称**Cache行**）由**若干字节**组成，**块的长度**称为**块长**（也称**行长**）。
	- **主存块**和Cache块**大小相等**！
		- **块的大小应适中**，不宜过大，也不宜过小。
		- 若**块大小过大**，Cache行数将会减少，**降低有效容量，增加缺失损失**（未命中时需从主存读取更多数据，传输时间更长。）
		- 若**块大小过小**，则**难以有效利用空间局部性**，命中率降低。

- 由于Cache的容量远小于主存的容量，所以**Cache中的块数**要**远少于主存中的块数**，Cache中**仅保存主存中最活跃的若干块的副本**。
- 因此，可按照某种策略**预测CPU在未来一段时间内待访存的数据**，将其装入Cache。

### Cache的访问过程
- 一句话：**先查Cache，未命中再查主存**。（真题遵循的方式）

- ![[第三章 3.5 高速缓冲存储器 cache访问过程.png]]

- **Cache命中**：所需信息**已在Cache中**。
- **Cache未命中**：也称**Cache缺失**，所需信息**不在Cache中**。

- CPU执行程序时，**每当需要从主存取指令或读/写数据时**，**首先访问 Cache**。
	1. 若**Cache命中**，则**直接从Cache读取，无需访问主存**。
	2. 若**Cache未命中**，则需**从主存中将该地址所在的一个主存块整体调入Cache**，即将该主存块复制到一个**空闲的Cache行**中。然后，CPU再从**刚复制好的Cache行中**获取所需数据。
		- 若**无空闲的Cache行**，则按**替换算法**选择被替换的行。

- 这些工作（包含**命中判断、块调入、替换**等工作）**要求在一条指令执行过程中完成**，因而**只能完全由硬件来实现**。
	- 因此，Cache对**程序员**来说是**透明的**， 程序员编程时**不用考虑信息存放在主存中还是在 Cache中**。

### Cache的命中率以及Cache-主存系统的平均访问时间
- $N_c$：**Cache命中次数**。
- $N_m$：Cache未命中次数，即**访问主存的次数**。

- Cache命中率：**Cache命中**的**概率**。它等于**命中次数**与**访问总次数**之比。
	- 设**命中率**为$H$，则有：
	- $$H = \frac{N_c}{N_c+N_m}$$
- Cache缺失率：**Cache不命中**的**概率**。它等于**不命中次数**与**访问总次数**之比。
	- $缺失率 = 1 - 命中率H$

- **命中时间**$T_c$：**访问Cache的时间**。
- **缺失损失**$T_m$：**访问主存的时间**，也是**从主存读入一个主存块到Cache行的时间**。

- 命中时，本次访存时间开销为$T_c$
- 未命中时， 本次访存时间开销为$T_c + T_m$
- 因此，Cache-主存系统的**平均访问时间**$T_a$为$$T_a = H × T_c + (1-H) ×(T_c+T_m) = T_c + (1-H)T_m$$
	- 由于**程序访问的局部性特点**，**Cache的命中率可以达到很高，接近于1**。
	- 因此，虽然$T_m>>T_c$。但最终的**平均访问时间仍可接近**$T_c$。

- 根据Cache的读写流程可知，实现Cache时需要解决以下关键问题。
	1. **在不在**？如何快速判断所需数据是否在Cache中。
	2. **放哪了**？主存块如何存放在Cache中，如何将主存地址转换为Cache地址。
	3. **换哪块**？当Cache已满时，采用何种策略选择被替换的Cache行。
	4. **怎么写**？如何在保证主存与Cache数据一致性的前提下，尽可能提升写操作效率。

## Cache和主存的映射方式
- CPU出厂时，**Cache-主存的映射方式已经在硬件层面固定**，因而无法动态切换。
- Cache标志位存储在每个Cache行的头部区域，CPU出厂时已经定好。

- 由于Cache行数远少于主存块数，Cache只能存放主存中部分块的副本。为**识别每个Cache行对应哪个主存块**，需要为**每行**设置一个**标记位**，**记录其主存块编号**。
	- 由于 Cache 的容量远小于主存，主存的**多个块**会映射到 Cache 的**同一个行号**上。比如主存第 0 块、第 8 块、第 16 块都映射到了 Cache 的第 0 行。
	- 仅靠行号找到 Cache 的第 0 行是**远远不够**的，因为 CPU **无法知道**这一行里装的到底是主存的第 0 块，还是第 8 块。
	- **标记位的作用**就是**存储原始主存块地址的高位部分**，将其作为该**主存块的独特标记**。CPU 访问时，会**提取自己发出地址的标记部分**，**与 Cache 当前行的标记位**进行**对比**。

- 与此同时，**每个Cache行**也设置一个**有效位**，用于**指示该行数据是否有效**。

- 在将主存块复制到Cache行时，主存块和Cache行之间**必须遵循**一定的**地址映射规则**。
	- 这样，CPU要访问某个主存单元时，可**依据映射规则到Cache 对应的行中查找信息**，而**不用在整个 Cache 中查找**。

- 根据不同的映射规则，主存块和Cache行之间有以下3种映射方式。
	- (1)**直接映射**(direct)：每个主存块**映射到Cache的固定行**中。 
	- (2)**全相映射**(full associate)：每个主存块**映射到Cache的任意行**中。
	- (3)**组相联映射**(set associate)：每个主存块**映射到Cache固定组的任意行**中。
	- 映射方式不同，其**Cache行的标记位所需的位数也不同**。

### 直接映射
- **直接映射**的基本思想：**把主存的每一块映射到固定的一个Cache行中**，也称**模映射**，其映射关系如下：$$\text{Cache行号} = \text{当前主存块号} \bmod  \text{Cache总行数}$$例如，假定Cache共有16行，根据100 mod 16 = 4可知，主存第100块应映射到Cache的第4 行中。
	- 若该Cache行**已有内容**，则发生**块冲突**，**原Cache行将被无条件替换**，而**无需替换算法**。
	- 直接映射方式**实现简单**，灵活性差，**即使其他位置有空行**，也**只能将主存块复制到固定的Cache行中**。
	- **块冲突概率最高，空间利用率最低**。
