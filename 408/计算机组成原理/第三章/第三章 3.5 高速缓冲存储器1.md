
## Cache
- 背景：
	- 程序的转移概率通常较高，数据分布也较为离散，因此**单纯依赖并行主存系统来提升主存效率是有限的**。
	- 在 CPU 与主存速度**差距不断拉大**的背景下，为了**缓解存储墙问题**，利用**程序局部性原理**，用**少量高速 SRAM 作为 Cache**，以**较低成本**实现**接近高速存储器的平均访问性能**。
		- CPU 访问一次主存的时间可能需要几十甚至上百个 CPU 周期，**CPU 大部分时间都在等待数据**，形成严重的性能瓶颈，即所谓的“**存储墙**”。

- **高速缓存（Cache）** 具有比**主存更快的访问速度**，因此在CPU与主存之间设置Cache可以**缓解 CPU 与主存之间的速度不匹配**，**显著提升**存储系统的整体效率。

- Cache 由 **SRAM**组成，通常**集成在 CPU 内部**。　

## 程序访问的局部性原理
- **程序访问的局部性原理**为引入 Cache **提供了理论依据**，Cache的设计基于程序访问的局部性原理。

- 程序访问的局部性原理包括**时间局部性**和**空间局部性**。
	- **时间局部性**：一个**数据或指令**被访问后，不久**很可能再次被访问**（如循环）。
		- 这源于程序中存**在循环、重复调用的子程序**，以及**对同一数据的多次操作**。
		- **循环内涉及的指令和数据**都具有较好的时间局部性。
	- **空间局部性**：如果某**存储单元**被访问，则其**邻近的存储单元**在不久的将来很可能也被访问。**（如顺序执行、数组遍历）。
		- 这是因为**指令通常顺序存放并顺序执行**，而**数据（如数组）也往往以连续块的形式存储**。
		- 空间局部性对**单个变量**没有意义，对**数组、指令**才有意义。
		- **连续存放的指令、数据**具有较好的空间局部性。

- 高速缓冲技术正是利用局部性原理，**将程序当前活跃的部分数据**暂存于**容量小但速度极快的Cache 中**，使CPU的**多数访存操作**直接**在Cache 中完成**，从而**显著提升程序执行效率**。

## Cache的基本工作原理
- 为**便于Cache与主存交换信息**，（⭐⭐⭐）
	- **Cache和主存**<span style="background:rgba(74, 82, 199, 0.2)">都被划分</span>为**大小相等的块**。
	- **Cache块**（也称**Cache行**）由**若干字节**组成，**块的长度**称为**块长**（也称**行长**）。
	- **主存块**和Cache块**大小相等**！
		- **块的大小应适中**，不宜过大，也不宜过小。
		- 若**块大小过大**，Cache行数将会减少，**降低有效容量，增加缺失损失**（未命中时需从主存读取更多数据，传输时间更长。）
		- 若**块大小过小**，则**难以有效利用空间局部性**，发生冲突的概率增大，命中率降低。
	- 通常**Cache的总行数**是**2的$n$次幂**。

- 由于**分块**，**主存地址结构**被划分为**主存块号 + 块内地址**。
- ![[第三章 3.5 高速缓冲存储器1 主存地址结构.png]]
- $$当前主存块号 = \lfloor \frac{当前主存地址}{块大小} \rfloor$$
	- 其中，**主存地址**为**字节地址**，**块大小**单位为**字节**。相当于**右移**。
- $$块内地址 = 主存地址 \bmod 块大小$$
	- 也就是**上面那个式子**的**余数**。

- 由于Cache的容量远小于主存的容量，所以**Cache中的块数**要**远少于主存中的块数**，Cache中**仅保存主存中最活跃的若干块的副本**。
- 因此，可按照某种策略**预测CPU在未来一段时间内待访存的数据**，将其装入Cache。

### Cache的访问过程
- 一句话：**先查Cache，未命中再查主存**。（真题遵循的方式）

- ![[第三章 3.5 高速缓冲存储器 cache访问过程.png]]

- **Cache命中**：所需信息**已在Cache中**。
- **Cache未命中**：也称**Cache缺失**，所需信息**不在Cache中**。

- CPU执行程序时，**每当需要从主存取指令或读/写数据时**，**首先访问 Cache**。
	1. 若**Cache命中**，则**CPU直接从Cache读取信息，无需访问主存**。
	2. 若**Cache未命中**，先将 **CPU 所需的那个特定字**（AD 单元内容）**直接送给 CPU**，与此同时，**将该字所在的整个主存块复制到 Cache 的空闲行中**。
		- 若**无空闲的Cache行**，则按**替换算法**选择被替换的行。

- 这些工作（包含**命中判断、块调入、替换**等工作）**要求在一条指令执行过程中完成**，因而**只能完全由硬件来实现**。
	- 因此，Cache对**程序员**来说是**透明的**， 程序员编程时**不用考虑信息存放在主存中还是在 Cache中**。

### Cache的命中率以及Cache-主存系统的平均访问时间

- $N_c$：**Cache命中次数**。
- $N_m$：Cache**未命中**次数，即**访问主存的次数**。

- Cache命中率：**Cache命中**的**概率**。它等于**命中次数**与**访问总次数**之比。
	- 设**命中率**为$H$，则有：
	- $$H = \frac{N_c}{N_c+N_m}$$
- Cache缺失率：**Cache不命中**的**概率**。它等于**不命中次数**与**访问总次数**之比。
	- $缺失率 = 1 - 命中率H$

- **命中时间**$T_c$：**访问Cache的时间**。
- **缺失损失**$T_m$：**访问主存的时间**，也是**从主存读入一个主存块到Cache行的时间**。
	- **命中时**，本次**访存时间开销**为$T_c$
	- **未命中时**， 本次**访存时间开销**为$T_c + T_m$
- 因此，Cache-主存系统的**平均访问时间**$T_a$为$$T_a = H × T_c + (1-H) ×(T_c+T_m) = T_c + (1-H)T_m$$
	- 由于**程序访问的局部性特点**，**Cache的命中率可以达到很高，接近于1**。
	- 因此，虽然$T_m>>T_c$。但最终的**平均访问时间仍可接近**$T_c$。

- 根据Cache的读写流程可知，实现Cache时需要解决以下关键问题。
	1. **在不在**？如何快速判断所需数据是否在Cache中。
	2. **放哪了**？主存块如何存放在Cache中，如何将主存地址转换为Cache地址。
	3. **换哪块**？当Cache已满时，采用何种策略选择被替换的Cache行。
	4. **怎么写**？如何在保证主存与Cache数据一致性的前提下，尽可能提升写操作效率。

## Cache和主存的映射方式
- CPU出厂时，**Cache-主存的映射方式已经在硬件层面固定**，因而无法动态切换。
- **Cache标志位**存储在每个Cache行的**头部区域**，CPU**出厂时已经定好**。

- 由于Cache行数远少于主存块数，Cache只能存放主存中部分块的副本。为**识别每个Cache行对应哪个主存块**，需要为**每行**设置一个**标记位**，**记录其主存块编号**。
	- 由于 Cache 的容量远小于主存，主存的**多个块**会映射到 Cache 的**同一个行号**上。比如主存第 0 块、第 8 块、第 16 块都映射到了 Cache 的第 0 行。
	- **仅靠行号**找到 Cache 的第 0 行是**远远不够**的，因为 CPU **无法知道**这一行里装的到底是主存的第 0 块，还是第 8 块。
	- **标记位的作用**就是**存储原始主存块地址的高位部分**，将其作为该**主存块的独特标记**（类似于数据库中的**关键字**）。CPU 访问时，会**提取自己发出地址的标记部分**，**与 Cache 当前行的标记位**进行**对比**。
- 与此同时，**每个Cache行**也设置一个**有效位**，用于**指示该行数据是否有效**。

- 在将主存块复制到Cache行时，主存块和Cache行之间**必须遵循**一定的**地址映射规则**。
	- 这样，CPU要访问某个主存单元时，可**依据映射规则到Cache 对应的行中查找信息**，而**不用在整个 Cache 中查找**。
- 根据不同的映射规则，主存块和Cache行之间有以下3种映射方式。
	- (1)**直接映射**(direct)：每个主存块**映射到Cache的固定行**中。 
	- (2)**全相联映射**(full associate)：每个主存块**映射到Cache的任意行**中。
	- (3)**组相联映射**(set associate)：每个主存块**映射到Cache固定组的任意行**中。
	- 映射方式不同，其**Cache行的标记位所需的位数也不同**。

- 通常**Cache的总行数**是**2的$n$次幂**。
- **Cache行 = 控制位 + 数据块** ^84f39f
	- **Cache 数据区(总)容量 = Cache 总行数 × 每行的数据块大小**
	- **控制位**（标记位、有效位、脏位）是**整行共享**的，不是每个字节一份（按字节编址）。
		- Cache 中有 **Tag RAM** 和 **Data RAM**，它们有自己的地址译码器、读写控制电路、独立的存储单元阵列。它们**物理上是独立的存储阵列，但在工作逻辑（访存机制）上紧密配合，可以看作是“逻辑相连”的**。
		- 当 CPU 给出一个主存地址时：
			1. **同一个索引**：地址中的**索引位（Index）** 会**同时**送入 Tag RAM 和 Data RAM 的地址输入端口。
			2. **并行读出**：在这两个独立的 RAM 中，各自位于该索引位置的那一行内容被同时读出。Tag RAM 读出了一串标记位，Data RAM 读出了一整个数据块。

- Cache和主存的映射本质上是**对主存地址中主存块号部分进行逻辑上的划分**。
	- 目标：从中划分出**可以唯一标识主存块的标志位**（类似于数据库中的关键字）。

### 直接映射
- **直接映射**的基本思想：**把主存的每一块映射到固定的一个Cache行中**，也称**模映射**，其映射关系如下：$$\text{Cache行号} = \text{当前主存块号} \bmod  \text{Cache总行数}$$例如，假定Cache共有16行，根据100 mod 16 = 4可知，主存**第100块**应映射到Cache的第4 行中。
	- 若该Cache行**已有内容**，则发生**块冲突**，**原Cache行将被无条件替换**，而**无需替换算法**。
	- 优点：**容易实现**，命中时间短。
	- 缺点：
		- 灵活性差，**即使其他位置有空行**，也**只能将主存块复制到固定的Cache行中**。
		- 由于是多对一的映射，会引起频繁的调进调出，**冲突概率高**，**命中率低**。
	- **块冲突概率最高，空间利用率最低**。

- 假定主存有$2^m$块，Cache有$2^c$行：
	- **主存地址 = 主存块号(m位) + 块内地址**
	- 主存块号 mod $2^c$：只保留**主存块号二进制**的**低c位**。（模运算的特性）
	- 由此可知，**m位主存块号**的**低c位**正好是它要装入的**Cache行号**。

- **标记位的设置**：将**主存块号**的**高t=m-c位**作为**主存块的独特标记**（关键字），即可唯一标识出该主存块，主存某块调入Cache后，就将其**块号的高t位**设置在**对应Cache行的标记**中。

- 根据以上分析可知，**主存地址被分成以下3个字段**：
	- ![[第三章 3.5 高速缓冲存储器 直接映射地址结构.png]]
	- 其中，**高t位为标记**，**中间c位为Cache行号**(也称**行索引**), 剩下的**b位为块内地址**。
	- 主存块号的位数 m = t + c
- ![[第三章 3.5 高速缓冲存储器 直接映射方式.png]]

- 访存过程如下：
	1. 首先根据**主存块号的低c位**，**直接找到对应的Cache行**。（先找Cache行）
	2. 将**对应Cache 行中的标记**和**主存地址的高t位标记**进行**比较**。（比较标记位）
		- 若**相等并有效位为1**，则Cache命中。 
			- 此时，根据主存地址中**低位的块内地址**，**在对应的Cache行的数据块中存取信息**。
		- 若**不相等或有效位 0**，则Cache不命中(缺失)。
			- 此时，CPU从**主存中**读出**该地址所在的一块信息**送到**对应的Cache行中**，将**有效位置1**，并**将标记设置为主存地址的高t位**，同时将**该地址中的内容**送CPU。

### 全相联映射
- 全相联，即**全随机**。
- **全相联映射**的基本思想是**一个主存块可装入Cache任意一行中**。全相联映射 cache 中，每行的标记**用于指出该行取自主存的哪个块**。
- 因为**一个主存块可能在任意一个Cache 行中**，所以CPU访存时需要**并行**比较**所有Cache行的标记**。 因此，主存地址中**无须Cache行索引**，**只有标记和块内地址两个字段**。

- **标记位的设置**：只有**将整个主存块号**作为**主存块的独特标记**（关键字），才能唯一标识出该主存块，因为此时无直接映射关系。

- 全相联映射时，主存地址结构如下：
	- ![[第三章 3.5 高速缓冲存储器 全相联映射地址结构.png]]
	- 其中，**标记即为主存块号**，标记位数t = 主存块号位数m。

- ![[第三章 3.5 高速缓冲存储器 全相联映射.png]]
- 访存过程如下：
	1. 首先将**主存地址**的**高位标记**（$位数=log_2主存块数$）与**每个Cache行**的标记**并行比较**。
	2. 若**有一个相等且对应有效位为1**，则Cache命中。
		- 此时根据块内地址从该Cache行中取出信息：
	3. 若**都不相等或有效位为0**，则Cache未命中。
		- 此时，CPU从**主存中**读出**该地址所在的一块信息**送到**Cache的任何一个空闲行**中，将**有效位置1**，并**将标记设置为地址中主存块号**，同时将**该地址中的内容**送CPU。

- 为了加快比较的速度，采用**并行比较**，通常**每个Cache行都设置一个比较器**，比较器位数等于标记字段的位数。
	- 访存时**根据标记字段的内容**查找Cache行中的主存块，因此**其查找过程是一种按内容访问的存取方式**，属于**相联存储器**。

- 全相联映射方式的**时间开销和所用元件开销都较大**，**实现起来比较困难**，不适合容量较大的 Cache。

### 组相联映射
- **模映射分组 + 组内随机放**。
- 直接映射和全相联映射的**优缺点正好相反**，二者结合可以**取长补短**。因此将两种方式**结合起来**产生了**组相联映射方式**。

- **组相联映射**的主要思想是：将所有Cache行**分成**$2^q$个**大小相等的组**，每组有$2^s$行。
- 每个主存块被映射到Cache**固定组**中的**任意一行**，即采用**组间模映射、组内全映射**的方式，映射关系如下：$$Cache组号 = 当前主存块号  \bmod Cache总组数$$
	- 例如，假定8KB的Cache划分为$2^3$组×$2^1$行/组×$512B$/行，则主存**第100块**应映射到Cache **第4组的任意一行**中，因为$100 \bmod 2^3=4$。

- 如此设置的$2^q$组×$2^s$行/组的Cache映射方式称为$2^s$**路组相联映射**。
	- **每组包含$r=2^s$个Cache行，则称为$r$路组相联。**
		- **路数r越大**，组内可选位置越多，**块冲突概率越低**，但**所需的比较器数量和控制逻辑也越复杂**。**合理选择r**，可在硬件成本接近直接映射的同时，获得接近全相联映射的性能。
	- **Cache总组数$2^q$ = Cache总行数**时，退化为**直接映射**。
	- **Cache总组数$2^q$ = 1**时，退化为**全相联映射**。

- 主存块号 mod $2^q$：只保留**主存块号二进制**的**低q位**。
- 由此可知，**m位主存块号**的**低q位**正好是它要装入的**Cache组号**。

- 假设**主存地址**有$n$位，**块内地址**占$k$位，有$2^t$个**组群**，则$n=t+q+ b$，主存地址被划分为以下3个字段：
	- ![[第三章 3.5 高速缓冲存储器 组相联地址结构.png]]
	- 其中，高$t$位为**标记**，中间$q$位为**组号**(也称**组索引**)，剩下的**b位低位地址部分为块内地址**，其中 主存块号位数m = t + q。
	- 标记字段的含义表示**当前地址所在的主存块位于主存中的哪个组群**。

- **标记位的设置**：将**主存块号**的**高t=m-q位**作为**主存块的独特标记**（关键字），即可**在该组中**唯一标识出该主存块，主存某块调入Cache后，就将其**块号的高t位**设置在**对应Cache行的标记**中。

- **组群**：是指**标记位（高 t 位）完全相同**的那一块**主存空间**。
	- 本质上是主存按**高位标记**划分出的**逻辑区域**。
	- **每一个组群里面，正好包含了 $2^q$ 个主存块**。
		- **组群在主存这边**：每个组群里有 $2^q$  个主存块。
		- **Cache 组在缓存这边**：Cache 里也有 $2^q$  个组。
	- 同一个“组群”里的这 $2^q$  个主存块，**只能**映射到 Cache 里对应的 $2^q$  个组中。
	- 也就是说，**每** $2^q$ **个主存块**与 $2^q$  个 Cache 组一一对应，**如下图所示**。
- ![[第三章 3.5 高速缓冲存储器 组项联映射方式.png]]

- 访存过程：
	1. 首先根据**访存地址中的组号字段**确定**目标Cache组**。
	2. 将**该组内所有Cache行的标记**与**主存地址的高位标记**<span style="background:rgba(74, 82, 199, 0.2)">并行比较</span>;
		- 若**某行标记匹配且其有效位为1**，则Cache命中。
			- 根据块内地址从该行读取数据。
		- 若**所有行均不匹配**或**匹配行的有效位为0**，则Cache未命中。
			- 此时，CPU从**主存中**读出**该地址所在的一块信息**送到**Cache对应组中的任何一个空闲行**中，将**有效位置1**，并**将标记设置为主存地址的高t位**，同时将**该地址中的内容**送CPU。

- 整个系统**比较器设置的个数 = 需要并行比较的Cache行最大个数**
	- **直接映射**中每块**仅对应一个唯一的Cache行**，因此只需设置 **1 个比较器**。
	- **全相联映射**需要**并行**比较**所有Cache行**，因此需设置 **Cache行数 个比较器**。
	- **r路组相联映射**需**在同一组的 r 个Cache 行中并行比较**，因此需设置 **r 个比较器**。

- 组相联映射的**冲突概率比直接映射低**。由于只有组内各行采用全相联映射，所以比较器的位数和个数都比全相联映射少， **易于实现，查找速度也快得多**。

### 3种映射方式比较
- **关联度**：指**一个主存块映射到Cache中时可能存放的位置个数**。
	- **直接映射**的关联度最低，为**1**。
	- **全相联映射**的关联度最高，为**Cache的总行数**。
	- **N 路组相联映射**的关联度居中，为**N**。
- 当**Cache大小、主存块大小一定**时，关联度和命中率、命中时间、标记所占额外开销等有如下关系：
	- (1)**关联度越低，命中率越低**。
		- 因此直接映射命中率**最低**，全相联映射命中率**最高**。
	- (2)**关联度越低，判断是否命中的开销越小，命中时间越短**。
		- 因此，直接映射的命中时间**最短**，全相联映射的命中时间**最长**。 
	- (3)**关联度越低，标记所占额外空间开销越少**。（例如**LRU位**）
		- 因此，直接映射额外空间开销**最少**，全相联映射额外空间开销**最大**。

| 映射方式  | 关联度          | 命中率 | 冲突概率 | 命中时间 | 标记额外空间开销 |
| ----- | ------------ | --- | ---- | ---- | -------- |
| 直接映射  | 1（最低）        | 最低  | 最高   | 最短   | 最少       |
| N路组相联 | N（居中）        | 居中  | 居中   | 居中   | 居中       |
| 全相联映射 | Cache总行数（最高） | 最高  | 最低   | 最长   | 最大       |
