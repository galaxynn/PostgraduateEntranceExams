- 本节以**单周期 + 专用结构数据通路**为例，介绍专用数据通路的设计原理。
	- 在单周期数据通路中，**每条指令的取指与执行均在一个时钟周期内完成**，CPU 的**时钟周期**必须以**最耗时的指令**为准。
	- 此外，由于**资源无法复用**，系统需要为**频繁使用的功能单元(如加法器)** 配置**多组独立的实例**。
	- 同时，为**避免指令获取与数据访问冲突**，指令和数据被**分别存储在独立的存储器中**，确保两者可在同一时钟周期内并行处理。
	- 注意：尽管基于单周期模型，但其中的**控制逻辑与数据通路设计思想**同样**适用于多周期、流水线等更复杂的结构**。

- 单周期数据通路**不需要显式的节拍信号来控制各阶段的执行顺序**，原因在于以下两点：
	- ① 数据通路中**各功能部件的物理连接顺序天然地隐含了微操作的先后时序**——数据从程序计数器出发，依次经过指令存储器、寄存器组、ALU、数据存储器等部件，**每一步的输出即为下一步的输入**，**组合逻辑的传播特性**保证了**数据沿既定路径自动完成全部处理**。
	- ② 时钟周期被设定为**不小于最长指令的关键路径延迟**，从而**确保在下一个时钟上升沿到来时，所有组合逻辑的输出均已稳定**，目标寄存器能够正确采样。换言之，时钟周期本身即是唯一的定时机制。

- 鉴于**完整**单周期数据通路结构较为复杂，以下将**结合具体指令执行过程**，**逐步拆解**其关键设计要点。

## 1. 取指令部件的设计
- 每条指令的**第一步**都是**完成取指令**并**计算下一条指令地址**的过程。
- 指令存储在**指令存储器**中，仅支持**读操作**。
- 读取指令时，只需提供**指令地址**，经过**固定的延迟**后即可**输出对应的32位指令字**。
	- 指令地址**由程序计数器(PC)提供**。
- ![[第五章 5.3专用结构的数据通路 取指令部件.png]]

- 取指令部件包含专用的**下地址逻辑电路**，用于**计算并更新 PC值**，以**确定下一条指令的地址**。
	- 下地址逻辑根据**当前指令类型**区分不同的执行路径: 
		- **顺序执行**：当指令为**普通顺序指令**时，**直接计算 PC+ 4** 得到下一条指令的地址。
		- **转移执行**：对于**分支或转移指令**，需要**根据指令类型计算转移目标地址**。
			- 例如，**beq 指令 (相等转移)** 通过比较两个寄存器的内容决定是否转移，并**根据偏移量计算新的PC值**。

- 注意：这是**不完整的取指令部件**，完整的请见最后的图。
- 由于单周期处理器**必须在一个时钟周期内完成指令**，其数据通路中**不设置指令寄存器(IR)**，而**直接从指令存储器中取指令并解析执行**，否则仅取指令到IR就需一个时钟周期。
## 2. R型运算类指令数据通路
- **R型指令**指的是**操作数全部来自通用寄存器**、**运算结果也写回通用寄存器**的**算术/逻辑运算指令**。
- ![[第五章 5.3专用结构的数据通路 R型指令.png]]

- ![[第五章 5.3专用结构的数据通路 R型.png]]
- 该数据通路能够**对两个寄存器 Rs 和Rt 的内容进行运算**，并将结果**写回 Rd 寄存器**。
	- add和sub等指令还需**判断运算结果是否溢出**，仅当**不溢出时才将结果写回Rd寄存器**。发生溢出时，会**触发异常处理**。
- ![[第五章 5.3专用结构的数据通路 通用寄存器.png]]
- 指令中的 Rs 和 Rt 是两个**源**操作数寄存器的编号，Rd是**目的**寄存器的编号。因此，
	- 寄存器堆的两个**读地址端Ra和Rb**应分别与Rs和Rt相连。
	- **写地址端Rw**应与Rd相连。
	- **ALU的运算结果**通过**总线busW**连至寄存器堆的**写数据端**。

- **控制信号RegWr**作为寄存器堆的**写使能信号**。
	- 在**R型指令**执行期间，**RegWr信号应始终为1**。
	- 在**RegWr为1且无溢出**的情况下，运算结果**才被写入寄存器堆**。
		- 具体来说，**RegWr信号**和**溢出标志位Overflow**通过 **“与”门组合** 后，决定是否允许写入寄存器堆。

- 此外，ALU 的操作类型由**控制信号 ALUctr/ALUop** 决定。
	- 假设 **ALU 支持 N 种不同的运算**，则 ALUctr **至少需要 $\lceil \log_2 N \rceil$ 位**来选择具体的运算类型。

## 3. I型运算类指令数据通路
- **I 型指令 = 一个寄存器操作数 + 一个立即数操作数**
- **I型运算指令**(立即数运算类指令)中的**其中一个操作数不是来自寄存器**，而是**直接编码在指令本身中的一个立即数**（Immediate）。
	- I型**运算**指令的核心执行逻辑是：
		- ① 先将指令中的16位立即数**扩展**为32位。（⭐）
		- ② 再**将寄存器Rs的内容送入ALU运算**
		- ③ 最后将**结果写回目的寄存器Rt**。

- 以有符号加法指令为例：`addi rt, rs, imm16 # R[rs] + SignExt[imm16] -> R[rt]`
- 其中,`SignExt[imm16]`表示对16位立即数进行**符号扩展**，即Sign Extension

- ![[第五章 5.3专用结构的数据通路 I型指令.png]]
- 与先前的数据通路相比，该数据通路主要有以下**三处改动**，以**同时兼容R型和I型运算指令的执行**。
	- `R型指令：add rd, rs, rt # R[rs] + R[rt] -> R[rd]`
	- `I型指令：addi rt, rs, imm16 # R[rs] + SignExt[imm16] -> R[rt]`
	- 核心思路：若某个端口**输入/输出**的**选择增加** -> 增设**多路选择器**（⭐）
	- 1)**目的寄存器选择**
		- R型指令使用目的寄存器Rd，而**I型指令使用目的寄存器Rt**。
		- 因此，在寄存器堆的**写地址端Rw处增设多路选择器**，由**控制信号RegDst**控制，**RegDst占1位**：
			- RegDst=1 (执行R型指令)时，选择**Rd为目的寄存器**。
			- RegDst=0 (执行I型指令)时，选择**Rt为目的寄存器**。
	- 2)**立即数扩展**
		- I型指令的**16位立即数**需**扩展为32位才能送入ALU**。
		- 数据通路中**新增一个立即数扩展器**，其输入为指令的imm16字段。由控制信号ExtOp决定扩展方式，**ExtOp占1位**：
			- 对于**算术类指令**（假设ExtOp=1），**关注立即数的正负**，把立即数当作有**符号整数**，必须**保持数值不变**，采用**符号扩展**。
			- 对于**按位逻辑操作指令**（ExtOp=0），不关注立即数正负，只需**保持低位的 bit 模式不变**，高位补 0 即可，采用**零扩展**。 
				- 例如：零扩展使高 16 位为 0，在 AND/OR/XOR 中分别表现为"清零/不变/不变"，**不会污染高位**。
	- 3)**ALU第二操作数选择**
		- R型指令的第二操作数来自寄存器Rt，I 型指令则**使用扩展后的立即数**。
		- 因此，在ALU的第二输入端增设多路选择器，由**控制信号ALUSrc**控制，**ALUSrc占1位**:
			- ALUSrc=0(执行R型指令)时，选择**寄存器Rt的数据**。
			- ALUSrc=1(执行I型指令)时，选择**扩展后的立即数**。

## 4.访存指令的数据通路
-  **I 型指令 = 一个寄存器操作数 + 一个立即数操作数**
- 在MIPS中，访存指令**属于I型指令**。
	- **访存指令**需要通过"**基址寄存器 + 偏移量立即数**"来**计算内存地址**，这种"一个寄存器 + 一个立即数"的操作数组合**正是 I 型指令的定义特征**；
	- 同时，在数据通路上，访存指令**复用了 I 型指令"寄存器 + 立即数 → ALU"的硬件路径**，因此被归为 I 型。
	- 例如：
		- `lw x1, 8(x2) # M[x2 + 8] -> x1，即 x1 = M[x2 + 8] 
		- 其作用是加载主存地址为(x2 + 8)的存储单元内容到x1寄存器中。
- 访存指令包含以下两类：
	- `LOAD指令：lw rt, imm16(rs) # M[R[rs] + SignExt(imm16)] -> R[rt]`
	- `STORE指令：sw rt, imm16(rs) # R[rt] -> M[R[rs] + SignExt(imm16)]`

- LOAD和STORE指令的**访存地址计算逻辑**完全一致：
	- **首先**对指令中的16位立即数imm16进行**符号扩展**，然后将其与寄存器Rs的内容相加，得到**访存地址**。
	- 二者区别在于**数据传输方向**：
		- LOAD指令从该地址**读取32位数据**，并将数据**写入寄存器Rt**。
		- STORE指令则将寄存器Rt中的32位数据**写入该地址对应的存储单元**。
- ![[第五章 5.3专用结构的数据通路 LOADSTORE.png]]
- 与先前的数据通路相比，该数据通路主要有以下**两处改动**，以**支持 LOAD/STORE 指令的执行**。
	- 1)**写回寄存器的数据选择**
		- 为了处理运算类指令与LOAD指令**写回寄存器的不同数据来源**，在寄存器堆的**写端口busW**处**增设一个多路选择器**，由**控制信号MemtoReg**控制，**控制信号MemtoReg占1位**:
			- MemtoReg=0(运算类指令)时，选择**ALU的运算结果**。
			- MemtoReg=1(LOAD指令)时，选择**数据存储器读出的数据**。
	- 2)**新增数据存储器模块**
		- 为了满足 LOAD/STORE 指令对数据存储器的读写需求，新增数据存储器模块。
		- **数据存储器**的**地址端Adr**直接连接到**ALU的输出端**(因为访存地址**由ALU计算得出**)。
		- **STORE指令**需要**将寄存器Rt的内容写入存储器**，因此将寄存器堆的**第二读端口busB**(对应寄存器Rb，即Rt)连接到**数据存储器**的**输入端DataIn**。
		- **数据存储器**的**输出端**接入**busW处的多路选择器**，用于**LOAD指令的读取结果写回**。
		- **控制信号MemWr**作为**数据存储器**的**写使能信号**(控制数据存储器的读/写操作)。
		- LOAD/STORE指令**计算访存地址时**，需要对**16位立即数imm16**进行**符号扩展**，并**通过ALU执行不判溢出的加法(addu)**（⭐，对上了！），此时**控制信号ALUctr**被配置为**addu对应的操作码**。 ^2cf0fc

- 综合以上分析，**单周期处理器/单周期数据通路**具有以下重要特点:
	- 1)**存储器分离设计**：**指令存储器与数据存储器相互独立**，使得取指令与数据访存操作可**并行进行**，避免冲突，确保在一个时钟周期内同时完成指令读取与数据读/写。
	- 2)**无指令寄存器(IR)**：指令从存储器取出后，其**各字段(如rs、t、rd、imm)直接用于生成控制信号或地址输入**，指令解析与执行**在同一个时钟周期内同步完成**。
	- 3)**时钟周期由最慢指令决定**：时钟周期必须满足执行时间最长的指令(如访存指令)，导致简单指令(如R型加法)的执行效率受限。
	- 4)**数据通路资源专用**：由于所有操作需要在一个周期内并发完成，关键功能单元(如用于PC更新和地址计算的**加法器**)需要**配置多个独立的实例**，硬件无法复用，**开销较大**。
	- 5)**控制信号单周期有效**：**所有控制信号**(如RegWr、MemWr等)**在一个时钟周期内始终保持有效**，指令“取指、执行、写回”的完整流程在单个时钟脉冲内完成，**无流水线分段**。
