## 常用汇编指令介绍
- 汇编指令通常可分为**数据传送指令**、**算术与逻辑运算指令**和**控制流指令**。

- 以下**用于操作数的标记**分别表示寄存器、内存和常数。
- `<reg>`：表示**任意寄存器**，若其后**带有数字，则指定其位数**。
	- `<reg32>`表示32位寄存器(eax,ebx, ecx, edx, esi, edi, esp或ebp);
	- `<reg16>`表示16位寄存器(ax, bx, cx或dx);
	- `<reg8>`表示8位寄存器(ah, al, bh, bl, ch,cl,dh, dI)，
- `<mem>`：表示**内存地址** (如[eax]、[var+4]或dword ptr [eax+ebx])。
- `<con>`：表示8位、16位或32位常数。
	- `<con8>`表示8位常数；
	- `<con16>`表示16位常数；
	- `<con32>`表示32位常数。

- x86 指令采用**变长编码**，其**操作码通常为1字节**，但**整条指令长度可变**。
	- 同一指令(如mov) 因**操作数类型或寄存器不同**，可能对应**多种机器码编码**，例如：
	- ![[第四章 程序的机器级代码表示 mov1.png]]

- `dword/word/byte ptr + [A]`：指明内存读写长度为**双字**/**单字**/**单字节**。
- [A]：表示取**寄存器或地址A**中的**内容**。类似于C语言中，**指针解引用**。

### 数据传送指令
#### 1. mov指令
- 格式：`mov dest, src ;dest <- src`
	- **操作数 = 数据本身 或 数据的存放地点**
	- **源操作数**可以是**立即数、寄存器或主存单元**，**目的操作数**可以是**寄存器或主存单元**，但**不能是立即数**。
- 作用：把1字节或**字**（需要显式表示）的**操作数**从**源地址 src** 传送至**目的地址 dest**。
```
mov al, 4; al <- 4，将立即数的值传送到al寄存器（立即数寻址）
mov byte ptr [2000h], 5 ; 将常数5存入地址 2000h 处的1字节内存单元（直接寻址），byte ptr 说明是字节操作
```
- **双操作数指令**的**两个操作数不能同时为内存**，即 mov 指令不能用于直接从内存复制到内存。 
	- 若**需在内存之间复制**，可先将**源内存内容加载到寄存器**，再**从该寄存器写入目标内存**。（利用**寄存器中转**。）

#### 2. push指令
- 格式：`push <reg32>/<mem>/<con32>`
- 作用：**将操作数压入栈中**，常用于**函数调用和现场保护**。
- 栈中元素**固定为32位**，即**4字节**。
- ESP是**栈顶指针寄存器**，入栈前**先将ESP减4**(栈向**低地址方向**增长)，再将操作数**压入**ESP所指地址。（先减，再压。）
	- 不变量：ESP指针**始终指向当前栈顶元素**。
```
push eax ; 将 eax 的值压栈
push [1000h] ; 将 地址1000h 处的 4字节内容 压入栈中
```

#### 3. pop指令
- 格式：`pop <reg32>/<mem>`
- 作用：与push指令相反，从栈中**弹出栈顶**，并将其**保存到指定位置**。
- 出栈前先将ESP所指地址的内容**读出**，再将**ESP加4**。（先读，再加。）
	- 不变量：ESP指针**始终指向当前栈顶元素**。

## 过程调用的机器级表示
- 在程序执行过程中，当**一个过程(函数)调用另一个过程**时，需要**完成参数传递、控制转移、现场保护与返回等一系列操作**。
- x86架构通过**call和ret指令**支持这一机制，它们都属于**无条件转移指令**，但配合**栈**的使用，实现了完整的“**调用-返回**”语义。

- 假定**过程P**(**调用者**)调用**过程Q**(**被调用者**)，整个**调用过程的执行步骤**如下:
	- 1) P将入口参数(**实参**)放到Q能访问的位置。
	- 2) P执行**call指令**，将**返回地址**(call的**下一条指令地址**)**压入栈**中，并**转移到Q**。
	- 3) Q建立自己的**栈帧**，为局部变量**分配空间**，并在必要时保存某些寄存器。
	- 4) Q执行其主体代码。
	- 5) Q将返回结果放到约定位置，释放局部变量空间，并**恢复之前保存的寄存器**。
	- 6) Q执行**ret指令**，从栈顶**弹出返回地址**，并转移回P继续执行。
	- 上述过程中，入口参数、返回地址、局部变量、返回结果以及需保护的寄存器内容，都需要**在内存中找到合适的存放位置**。

- 由于寄存器数量有限，且**调用双方共享寄存器资源**，若不加保护，直接覆盖，将导致程序出错。因此，**调用约定**和**栈**的配合至关重要。（类似于**进程同步机制**）

- 有如下规定：
	- ① 寄存器 EAX、ECX 、EDX是**调用者(P)保存寄存器**。
		- 即调用者**需要保存**的寄存器，如果**调用完还想用**，**调用前**先保存。
		- **被调用者**在调用过程中可以**直接使用**。
		- 若P希望**在调用后仍使用**这些寄存器的值，则P必须**在调用前自行保存**(如压栈)，并在**返回后恢复**。
	- ② 寄存器 EBX、ESI、EDI是**被调用者(Q)保存寄存器**
		- 即被调用者**需要保存**的寄存器，如果**调用时想用**，**使用前**先保存。
		- **被调用者**在调用过程中**不能直接使用**。
		- 若Q需要使用这些寄存器，则Q必须**在使用前将其保存到栈中**，并**在返回前恢复**。

- **每个过程**在执行时，都会**在运行时栈（函数调用栈）中分配一块专属区域**，称为**栈帧**。

- 整个**运行时栈（函数调用栈）** 由**多个连续的栈帧**组成。
	- 栈**从高地址向低地址增长**。（⭐⭐）

- EBP(基址指针)指向**当前栈帧的基址**，ESP(栈指针) 始终指向**当前栈帧的栈顶**。
	- 过程执行时，**ESP**会**随数据入栈/出栈动态变化**，而**EBP**在当前过程执行期间**保持不变**，便于**通过固定偏移访问参数和局部变量**。
