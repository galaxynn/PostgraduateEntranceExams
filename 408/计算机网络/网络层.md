
## IP分组分片
- IP分组的**最大总长度**：$2^{16} - 1 = 65535 B$
- 当**IP分组的长度** ≥ **数据链路层的MTU**(最大传送单元)时，则需要对该**IP分组的有效载荷**(即数据部分，**不含首部**)进行**分片**。
	- 数据链路层MTU(**能承载的最大数据量**)若**未说明**，则**默认为1500B**（以太网帧的最大数据长度。）

- 已知：IP分组总长度(首部 + 有效载荷长度)，IP分组首部长度。
- 隐含条件：**字节从0开始“编号”**，**分片从1开始“编号”**。

1. 计算**IP分组中有效载荷(数据部分)的总长度**
	- $有效载荷长度 = 总长度 - 首部长度$ (单位:B)
2. 确定**一个分组最多能承载多少数据**。
	- $理想承载数据量 = MTU - 首部长度$ (单位:B)
	- **必须**要**验证**实际承载数据量是否“理想”，即**是否是8的倍数**。（重要⭐⭐）
		- **实际承载数据量必须是8的倍数**，是由片偏移字段的单位决定的：8B。
	- **验证方法**：计算$\frac{理想承载数据量}{8}$
		- 如果**能够整除**，
			- 则 $实际承载数据量 = 理想承载数据量$。
		- 如果**不能整除**，记**余数**为$R$，
			- 则 $实际承载数据量 = 理想承载数据量 - R$
3. 确定**分片数量**。
	- $分片数量 = \lceil \frac{有效载荷长度}{实际承载数据量} \rceil$
	- 可根据分片数量，判断某一分片的**MF标志位**。
4. 计算某分片的**起始字节编号**和**末尾字节编号**、**片偏移**。
	- $起始字节编号 = (片号 - 1) × 实际承载数据量$
	- $$末尾字节编号 = 起始字节编号 + 实际承载数据量 - 1 = 片号 × 实际承载数据量 - 1$$
	- $片偏移 = \frac{起始字节编号}{8}$ 


## IP地址
- 推荐记一下**常用的数字**：
	- 1100 0000：192
	- 1110 0000：224
	- 1111 0000：240

- 整个的互联网就是一个单一的、抽象的网络。
- IP地址就是给连接到互联网上的**每一台主机(或路由器)** 的**每一个接口**，分配一个**在全世界范围内是唯一的32位的标识符**。IP地址的结构使我们可以在互联网上很方便地进行寻址。

- IP地址记法： ![[网络层 点分十进制.png]]

- IP地址不但标志了主机(或路由器)，而且还标志了此接口所连接的网络。
- 32位的IP地址采用**两级结构**，由**两个字段**组成。
	- 第一个字段是**网络号**，它标志主机(或路由器)所连接到的网络。
		- 一个网络号在**整个互联网范围**内必须是唯一的。
	- 第二个字段是**主机号**，它标志该主机(对路由器来说，就是标志该路由器)。
		- 一个主机号在**所连接的网络**中必须是唯一的。
	- 由此可见，**一个IP地址在整个互联网范围内是唯一的**。
- 因此，IP地址可以记为：
	- IP地址 := {<网络号>，<主机号>}
	- ![[网络层 IP地址字段.png]]

### 分类的IP地址
- 在互联网发展早期采用的是**分类的IP地址**，也就是在图4-9中的$n$是**固定的几个数之一**。
- ![[网络层 分类.png]]
- ![[网络层 分类-1.png]]
- 如图所示，分类的方法非常简单，A类(n=8)、B类(n=16)和C类(n=24)地址都是**单播地址**。D类是**多播地址**(一对多通信)，而E类是**保留地址**。
- 如果给出一个二进制数表示的**IP单播地址**，那么就可以很容易地从**网络号的前几位**知道是哪类地址，并且也能看出这个二进制数表示的网络号和主机号。

- ![[网络层 数量.png]]

- 特殊的**网络号**：
	- **网络号为0**的IP地址有特殊的用途，它表示“本网络”。
	- **网络号为127**(即01111111) 保留作为**本地软件环回测试**本主机的进程之间的通信之用。
		- 路由器收到目的IP地址为127.0.0.1的IP分组时，直接丢弃。

- 特殊的**主机号**：
	- 主机号**全为0**：表示**本网络本身**(网络地址)，例如 202.98.174.0。
	- 主机号**全为1**：表示本网络的**广播地址**，也称**直接广播地址**，例如 202.98.174.255。

- 特殊的**地址**：
	- **32位全为0**，即 0.0.0.0：表示本网络上的本主机(常用于 DHCP，作为源IP地址)。
	- **32位全为1**，即255.255.255.255：表示**受限广播地址**，仅在<font color="#ff0000">本网络</font>内广播。
		- 路由器收到目的IP地址为255.255.255.255的IP分组时，直接丢弃。

### 无分类编址 CIDR
- CIDR 把图 4-9 中的**网络号**改称为“**网络前缀**”(或简称为“前缀”), 用来指明网络，剩下的后面部分仍然是主机号，用来指明主机。在有些文献中也把主机号字段称为后缀。

- CIDR的记法是:
	- IP地址 ::= {<网络前缀>,<主机号>}
	- ![[网络层 cidr.png]]
- 网络前缀的位数$n$**不再是固定的数**，而是**可以在0~32之间选取任意的值**。
- CIDR 使用“**斜线记法**”，或称为**CIDR 记法**，即在 IP地址后面加上斜线“/”，斜线后面是**网络前缀所占的位数**。

- CIDR 把**网络前缀都相同的所有连续的IP地址**组成一个“**CIDR 地址块**”。一个 CIDR 地址块包含的IP地址数目，取决于网络前缀的位数。
- ![[网络层 地址块.png]] 

- CIDR 使用斜线记法可以让我们知道网络前缀的数值。但是**计算机看不见斜线记法**，而是使用二进制来进行各种计算，必须使用32位的**地址掩码**才能够从IP地址迅速算出网络地址。

- **地址掩码**(常简称为掩码)由**一连串1和接着的一连串0组成**，而**1的个数就是网络前缀的长度**。地址掩码又称为**子网掩码**。
- CIDR 记法中，斜线后面的数字就是**地址掩码中1的个数**。

 - 对于**早期使用的分类 IP地址，其地址掩码是固定的**，常常不用专门指出。例如：
	 - A类网络，地址掩码为255.0.0.0或255.0.0.0/8
	 - B类网络，地址掩码为255.255.0.0 或255.255.0.0/16
	 - C类网络，地址掩码为255.255.255.0或255.255.255.0/24。

- 计算机把二进制的IP地址和地址掩码进行**按位 AND 运算**，即可得出**网络地址**。

- CIDR 地址中还有三个特殊地址块：
	- (1) 前缀n = 32，即32位IP地址都是前缀，**没有主机号**。这其实就是一个IP地址。这个特殊地址用于**特定主机路由**。

## 子网划分

- 通常有**两类**划分子网的方法：采用**定长子网掩码**和**变长子网掩码**。

- 采用CIDR后，**IP地址 = 网络前缀字段 + 主机号字段**
- **子网划分是在某个单位的网络内部进行的**，外部不可见也无需可见内部子网划分的细节。

- 注意，**主机号字段的长度至少为1**。
	- 按**最新标准**，主机号字段长度为1时（即前缀长度为/31时），可用于**点对点连接两个路由器**，**无需保留**网络地址和广播地址。
	- 但有的题目，**需要保留**网络地址和广播地址，此时**前缀长度最大为/30**。

### 1.定长子网掩码划分子网
- **核心思路**：从**主机号字段**中**划分出固定长度的子网号字段**，每个子网的主机号字段长度**相同**。
	- 每个子网的“网络前缀字段 + 子网号字段”的长度相同。

- 假设要划分出$m$**个子网**，则将主机号字段的高 $r = \lceil \log_2m \rceil$位，作为**子网号字段**。
- 假设**划分前**主机号字段的长度为$n$位，则**划分后**，**主机号字段的位数**为$n - r$位，即在每个子网中可表示$2^{n-r}$个**地址**，可表示$2^{n-r} - 2$个**主机**。

- 多划分出来的子网，将**保留**，可见该方法的**地址空间利用率不高**。

### 2. 变长子网掩码划分子网
- 每个子网的“网络前缀字段 + 子网号字段”的长度可以不同，即主机号字段长度不同，**更灵活，地址空间利用率更高**。

- 划分方法：**二叉树划分法**。
	- 原理：[[第五章 树与二叉树的应用#^f7fc2c]]

## 路由器相关
- **路由表/转发表表项**记录的是 {**目的网络地址**，**下一跳地址**，**接口**}
	- 路由器有**全局观**，所以可以知道**目的网络地址**该往哪走。
	- **下一跳地址**指的是**下一跳路由器接口的地址**。
	- **接口**指的是从当前路由器的哪个接口转发出去，与以太网交换机类似，以太网交换机中没有“下一条地址”。

- 路由器进行**NAT**时，私网IP地址所映射的**公网IP地址**是**连接外网的接口对应的IP地址**。
	- **没给出NAT转换表时**，就这样判断。
	- 给出NAT转换表时，直接根据其表项映射即可。
		- 内网访问内网时，路由器**自动**在NAT转换表中创建映射关系，注意端口也要换，其端口号是**随机分配**的。
		- 若想让**外网访问内网**，需要**手动创建映射关系**。

## 地址解析协议（ARP）
- IP分组被封装成MAC帧发送到路由器后，路由器会**将MAC帧解封装**，取出IP分组，交给网络层处理，以**判断下一跳地址和接口**。

- MAC帧被解拆封后，**源MAC地址和目的MAC地址随即消失**，这决定了**MAC地址无法用于跨网络通信**。

- 路由器**确认了下一跳、修改IP分组的TTL和首部校验和后**，会将IP分组**重新封装成MAC帧**，MAC帧的**源MAC地址**和**目的MAC地址**都**随之“改变”**（事实上，是一个**新封装的MAC帧**，不是原来的MAC帧了，**FCS重新计算**。）
	- 由此可知，每经过一个路由器，以下内容发生改变：
		- 整个MAC帧（或者说**源MAC地址、目的MAC地址、FCS字段**）
		- IP首部中的**TTL字段**，**首部校验和字段**。

- 问：重新封装时，如何知道确定**目的MAC地址**？
- 答：利用ARP，将**目的IP地址**对应的**目的MAC地址**。

- 每台路由器和主机都**动态维护**一个**ARP高速缓存**，用于存放<font color="#ff0000">本局域网内</font>各主机和路由器接口的<u>IP地址与MAC地址的映射表</u>，称为**ARP表**。
	- 某个表项都有“**生存时间**”，超时的条目将被删除。

- ARP工作在**网络层**，核心功能是**解析**<font color="#ff0000">同一个局域网</font>内**IP地址对应的MAC地址**。
